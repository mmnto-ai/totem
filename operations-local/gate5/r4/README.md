# Gate (5) — the R4 severity-lowering controls (mmnto-ai/totem#3044)

The harness half of the lift ruling's Q1 (a′) mechanism (mmnto-ai/totem-strategy#1486, the Q1 addendum's (ii)): the migration harness's fidelity leg admits one expected divergence, a record severity LOWER than its legacy row's, for a rule the ruling names under ADR-103's R4 clause. This directory holds the controls that measure that admission and every refusal around it.

## The contract (what the scorer's § 7 entry mirrors)

- **The allow-list.** `R4_SEVERITY_LOWERING_RULES` in `operations-local/gate5/mig-harness.mjs`, a NAMED export whose value is one array literal of plain single-quoted lowercase 16-hex hashes, so a parity control can read it from the file's source blob at `pin.harness.commit` by a deterministic parse. Today: `2266fc0dfe824f24` (the static named import from the core barrel) and `87aff037d7de47a7` (the fail-open catch ban). The DATE for (a′), 2026-11-16, set by the operator on 2026-10-10 and movable by re-ruling, is cited in the constant's comment and is not a mechanism: nothing keys on the clock; the list changes by a commit on a further ruling.
- **The grammar the parity control refuses outside.** A positive list, nothing else admitted. Exactly one line of the form `export const R4_SEVERITY_LOWERING_RULES = ['<16 lowercase hex>', ...];` whose bracket body is fully consumed by single-quoted lowercase 16-hex tokens and commas (no spread, no identifier, no double quote, no upper case, no residue, no repeated hash). The line `Object.freeze(R4_SEVERITY_LOWERING_RULES);` (the runtime freeze) must be the first line after the declaration that is not a `//` comment line, so nothing can execute between the literal and the freeze. Every other occurrence of the identifier in the file must be one of exactly three forms: the token immediately followed by `.includes(`, the token immediately followed by `.join(`, or a mention on a `//` comment line (a line whose first non-blank characters are `//`; block-comment lines are NOT exempt, because a line's first characters cannot tell a comment from code that follows one). Any other occurrence is a violation: whitespace or a comment before a member access, an optional-chaining access, an assignment to any member, an alias, the token as an argument to any call, the token inside a callback or a template literal, a line starting with `*` or `/*`, a second declaration anywhere (a decoy inside a block comment or a template literal counts as a second declaration), a shadowing binding, a freeze line anywhere but its place. The source must carry no line terminator the grammar does not split on — a bare CR (not followed by LF), U+2028 LINE SEPARATOR or U+2029 PARAGRAPH SEPARATOR — anywhere, a string literal included: JavaScript ends a line and a `//` comment at those, the scan splits on LF alone, so a shadowing binding after one of them on a `//` line would be exempt here and bound at run time; the refusal is source-wide and fail-closed, read before the split (mmnto-ai/totem#3087, found by the strategy scorer's eighth-entry read 2; strategy's `parseR4AllowList` refuses the same three bytes, so the two grammars give one verdict on every source that names the identifier; a source that never names it is refused here, as a source with no declaration line (the violation reads "expected exactly one declaration line, found 0"), and read as absent by the mirror, which keys on that to mark a harness predating the mechanism — the one verdict pair that differs, by design on the strategy side). A0 applies this grammar to the committed source, to a valid base and the three allowed forms (each accepted) and to thirty-five wrong sources (each refused, built on the valid base so the violation reported is the defect's own): the five read 1 named; the eleven widening shapes read 2 named and its non-widening length write; the seven shapes read 3 named (code after a block-comment opener, a `*` continuation line, a template-literal interior, a decoy declaration inside a block comment and inside a template literal, a freeze under `if (0)`, a freeze inside a block comment); the shape CodeRabbit named on the pull request (a decoy in a block comment plus the real declaration spelled with a backslash-u hex escape inside the identifier, which binds the same name); a repeated hash, an indexed write, a shadowing binding, a missing freeze line, a double declaration and a block-comment mention; and the four stray-terminator shapes mmnto-ai/totem#3087 named (a shadowing declaration after a bare CR, after U+2028 and after U+2029 on a `//` line, and U+2028 inside a string literal), each refused by the terminator clause itself and not by a later clause. Escapes inside identifiers are decoded per line, after the split, so an escaped spelling is read as the identifier it binds and an escaped newline inside a string literal never creates a line. **The limit, stated:** a source grammar sees occurrences of the identifier and nothing else; a mutation that never names it (an `Array.prototype.includes` override, a reflective write through a computed name) is invisible to it. That is why the harness also freezes the array: under ESM strict mode every write to it after the freeze throws, whatever the route, and the placement rule above leaves no line that can run between the literal and the freeze, so the runtime list is the literal or the run dies.
- **The inventory item.** `iv`, "severity lowered under R4", declared per lessonHash in the batch inventory's `inventory[]` beside `i`, `ii`, `iii`.
- **Its semantics.** Admissible only in `--set` mode (any run without `--set` refuses it: the K3 regression and a seed run without the `--r14` flag alike); only on a hash in the allow-list; never beside `ii`. Each of those three is refused at inventory read, over the WHOLE inventory (every key that carries an `inventory` array, whatever its spelling, underscore-prefixed keys included), before any record is read (exit 2) — a declaration on a hash outside the manifest and the `--only` selection is refused too. An `--only` that selects no entry is refused first (exit 2, stderr naming every unmatched token), before the inventory is read, so a typo or a stale batch file never runs zero records and passes vacuously; a partial match runs the matched entries and names the unmatched tokens on stdout (mmnto-ai/totem#3082). Lowering only: record `warning` against legacy `error`, the closed `RuleSeveritySchema` pair. Equal severity under a declaration reads identical, with one stdout note, printed directly after the record's own line and naming the record file, that the declaration is inert. A raise, an undeclared lowering, or a severity outside the pair on either side stays `unexpected` carrying `severity` (exit 1).
- **The row.** No new key. `fidelity.severity` stays the measured equality (false on a lowering); `fidelity.expectedDivergence` carries the string `severity (inventory iv: lowered under R4)`; `fidelity.declaredInventory` may contain `iv`; `unexpected` is empty. `harness-record.schema.json` moved with it: the `declaredInventory` items enum gained `iv`.

## The controls

`controls-r4.mjs` spawns the harness over fixtures DERIVED under `--scratch` from the pin's own records and manifest (a lowered copy asserts its one-line delta, the K5b pattern; the R14 records and the base harness come from `git show`). Nothing is committed but this script, this file and the run log; `--scratch` must be new or empty, and `--out` defaults to the run log beside the script, so a re-run REPLACES the run of record on purpose and the diff shows it.

```text
node operations-local/gate5/r4/controls-r4.mjs --scratch <new or empty dir> \
  --seed <strategy>/operations/310-r14-audit/seed-20.json \
  --corpus <strategy>/operations/310-r14-audit/inputs/compiled-rules.json \
  [--core <@mmnto/totem package dir>] [--r14-pin 78e7f196] [--base b1792d5a] [--out <log>]
```
