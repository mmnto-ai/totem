# Gate (5) — the R4 severity-lowering controls (mmnto-ai/totem#3044)

The harness half of the lift ruling's Q1 (a′) mechanism (mmnto-ai/totem-strategy#1486, the Q1 addendum's (ii)): the migration harness's fidelity leg admits one expected divergence, a record severity LOWER than its legacy row's, for a rule the ruling names under ADR-103's R4 clause. This directory holds the controls that measure that admission and every refusal around it.

## The contract (what the scorer's § 7 entry mirrors)

- **The allow-list.** `R4_SEVERITY_LOWERING_RULES` in `operations-local/gate5/mig-harness.mjs`, a NAMED export whose value is one array literal of plain single-quoted lowercase 16-hex hashes, so a parity control can read it from the file's source blob at `pin.harness.commit` by a deterministic parse. Today: `2266fc0dfe824f24` (the static named import from the core barrel) and `87aff037d7de47a7` (the fail-open catch ban). The DATE for (a′), 2026-11-16, set by the operator on 2026-10-10 and movable by re-ruling, is cited in the constant's comment and is not a mechanism: nothing keys on the clock; the list changes by a commit on a further ruling.
- **The grammar the parity control refuses outside.** A positive list, nothing else admitted. Exactly one line of the form `export const R4_SEVERITY_LOWERING_RULES = ['<16 lowercase hex>', ...];` whose bracket body is fully consumed by single-quoted lowercase 16-hex tokens and commas (no spread, no identifier, no double quote, no upper case, no residue, no repeated hash). The line `Object.freeze(R4_SEVERITY_LOWERING_RULES);` (the runtime freeze) must be the first line after the declaration that is not a `//` comment line, so nothing can execute between the literal and the freeze. Every other occurrence of the identifier in the file must be one of exactly three forms: the token immediately followed by `.includes(`, the token immediately followed by `.join(`, or a mention on a `//` comment line (a line whose first non-blank characters are `//`; block-comment lines are NOT exempt, because a line's first characters cannot tell a comment from code that follows one). Any other occurrence is a violation: whitespace or a comment before a member access, an optional-chaining access, an assignment to any member, an alias, the token as an argument to any call, the token inside a callback or a template literal, a line starting with `*` or `/*`, a second declaration anywhere (a decoy inside a block comment or a template literal counts as a second declaration), a shadowing binding, a freeze line anywhere but its place. A0 applies this grammar to the committed source, to a valid base and the three allowed forms (each accepted) and to thirty wrong sources (each refused, built on the valid base so the violation reported is the defect's own): the five read 1 named; the eleven widening shapes read 2 named and its non-widening length write; the seven shapes read 3 named (code after a block-comment opener, a `*` continuation line, a template-literal interior, a decoy declaration inside a block comment and inside a template literal, a freeze under `if (0)`, a freeze inside a block comment); and a repeated hash, an indexed write, a shadowing binding, a missing freeze line, a double declaration and a block-comment mention. **The limit, stated:** a source grammar sees occurrences of the identifier and nothing else; a mutation that never names it (an `Array.prototype.includes` override, a reflective write through a computed name) is invisible to it. That is why the harness also freezes the array: under ESM strict mode every write to it after the freeze throws, whatever the route, and the placement rule above leaves no line that can run between the literal and the freeze, so the runtime list is the literal or the run dies.
- **The inventory item.** `iv`, "severity lowered under R4", declared per lessonHash in the batch inventory's `inventory[]` beside `i`, `ii`, `iii`.
- **Its semantics.** Admissible only in `--set` mode; only on a hash in the allow-list; never beside `ii`. Each of those three is refused at inventory read, over the WHOLE inventory, before any record is read (exit 2) — a declaration on a hash outside the manifest and the `--only` selection is refused too. Lowering only: record `warning` against legacy `error`, the closed `RuleSeveritySchema` pair. Equal severity under a declaration reads identical, with one stdout note, printed directly after the record's own line and naming the record file, that the declaration is inert. A raise, an undeclared lowering, or a severity outside the pair on either side stays `unexpected` carrying `severity` (exit 1).
- **The row.** No new key. `fidelity.severity` stays the measured equality (false on a lowering); `fidelity.expectedDivergence` carries the string `severity (inventory iv: lowered under R4)`; `fidelity.declaredInventory` may contain `iv`; `unexpected` is empty. `harness-record.schema.json` moved with it: the `declaredInventory` items enum gained `iv`.

## The controls

`controls-r4.mjs` spawns the harness over fixtures DERIVED under `--scratch` from the pin's own records and manifest (a lowered copy asserts its one-line delta, the K5b pattern; the R14 records and the base harness come from `git show`). Nothing is committed but this script, this file and the run log; `--scratch` must be new or empty, and `--out` defaults to the run log beside the script, so a re-run REPLACES the run of record on purpose and the diff shows it.

```text
node operations-local/gate5/r4/controls-r4.mjs --scratch <new or empty dir> \
  --seed <strategy>/operations/310-r14-audit/seed-20.json \
  --corpus <strategy>/operations/310-r14-audit/inputs/compiled-rules.json \
  [--core <@mmnto/totem package dir>] [--r14-pin 78e7f196] [--base b1792d5a] [--out <log>]
```
