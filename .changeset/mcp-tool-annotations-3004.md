The four MCP tools (`search_knowledge`, `describe_project`, `add_lesson`, `verify_execution`) now declare `readOnlyHint`, `destructiveHint` and `openWorldHint` explicitly, judged over the project's git-tracked content with Totem's own local state under `.totem/` not counted, so a client no longer falls back to the schema defaults. `verify_execution` is now declared not read-only and destructive: on a pending pack promotion the lint it spawns rewrites the tracked `compiled-rules.json` in place and writes `verification-outcomes.json`, and on every run that evaluates rules it writes rule metrics, telemetry and, on a suppression, a Trap Ledger event under ignored `.totem/` paths. `openWorldHint` is `true` on `search_knowledge` and `add_lesson`, which send text to the configured embedding provider, which may be remote, and on `verify_execution` until mmnto-ai/totem#3008 lands, because its spawn arm may reach the npm registry; the vector index store at the configured `lanceDir` is in the not-counted class (a reader never rebuilds it, mmnto-ai/totem#3009); and each tool's description now carries a one-clause disclosure of what it writes. The rich-state `git status` read in `describe_project` no longer takes git's optional index lock. `totem init` now writes the `.gitignore` lines for Totem's local state (`.totem/ledger/`, `.totem/cache/`, `.totem/temp/`, `.totem/*.jsonl`, the sync lock, the index manifest and the pack files) under the configured `totemDir`, in bare mode too, adding only the lines a project lacks and never one the project has re-included with `!`, in one atomic write under one `# Totem` header. A test pins the four annotation objects through the server's advertised `tools/list`; the README states the rule and discloses each tool's writes (mmnto-ai/totem#3004).
