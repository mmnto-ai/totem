`zod` moves from `^3.24.0` to `^4.6.7` in `@mmnto/totem`, `@mmnto/cli` and `@mmnto/mcp`, so a consumer's lockfile stops resolving `zod@3.25.76`, the version GHSA-mrhx-c7xc-m3w5 (CVE-2023-54404, high: an oversized array against an unbounded array schema accumulates one issue object per failing element with no cap) names as vulnerable below 4.6.6, with no patched 3.x release on the registry (mmnto-ai/totem#3141). Every parsed result is unchanged. The single-argument `z.record(value)` form zod 4 removed becomes `z.record(z.string(), value)` at its seventeen sites. The three object-valued config defaults (`review`, `hooks.legsOwed`, `hooks.shield`) move from `.default({})` to `.prefault({})`, because zod 4's `.default()` returns its value without parsing it, and the inner defaults (`sourceExtensions`, `legsOwed.globs`) would no longer fill when the block is absent. The exported `DoctorConfigSchema` loses its block-level default instead: the config attaches it as optional, and zod 4's optional applies an inner default where zod 3 returned `undefined`, so a config that never declared `doctor` would have parsed to a filled block; an empty `doctor: {}` still fills `staleRuleWindow`, and a config without the block still reads `undefined`. The selection manifest's enum-keyed `context` becomes a `partialRecord`, since zod 4's enum-keyed `record` requires every key where zod 3 accepted a subset. The ledger's `session_id` and `correlation_id` and the selection manifest's two session ids move from `.uuid()` to `.guid()`, zod 4's name for the 8-4-4-4-12 hex shape zod 3's `.uuid()` accepted, so a row written by an earlier release still parses (zod 4's `.uuid()` also requires the RFC 4122 variant bits). The three refinements that interpolated the offending value into their message and the one `required_error` move to zod 4's `error` map with the same texts. The exported schema objects (`LessonFrontmatterSchema`, the artifact, config and record schemas) are now zod 4 instances, so a consumer that composes them with its own zod 3 schemas needs zod 4 too; no such consumer is known, which is why this ships as a minor rather than a major. `openai` 4.x declares an optional peer on zod 3 that is now unmet: pnpm prints one warning per install, here and in every consumer, and nothing loads, because Totem never imports `openai/helpers/zod`; the `openai` 6 bump that clears the warning is a follow-up. Deprecated-but-working zod APIs (`.strict()`, `.passthrough()`, `.datetime()`, `z.ZodIssueCode`, `{ message }` params) are untouched. Zod's own default error texts changed between the majors (for example "Required" now reads "Invalid input: expected string, received undefined", and an unknown key in a strict object reads `Unrecognized key: "x"` where it read `Unrecognized key(s) in object: 'x'`), so a Totem message whose tail quotes zod's wording, such as the action-policy refusal of a misspelled row or scope key, reads differently; Totem's own texts are unchanged.
