Every patch- or stat-producing `git diff` Totem reads, and the two `git log -p` reads, now carry eight porcelain pins directly after the subcommand, `--no-ext-diff --no-textconv --no-color --no-relative --unified=3 --submodule=short --src-prefix=a/ --dst-prefix=b/`, exported from `@mmnto/totem` as `GIT_DIFF_PORCELAIN_ARGS` (mmnto-ai/totem#3113). Before this, every diff `totem lint` and `totem review` graded came from `git diff` with the user's and the repository's git config in force, and the parsers assumed git's default text. Each flag fixes the one output property the parsers assume, measured on git 2.56 in a throwaway repository: with `diff.external` set (difftastic's documented setup), the gate read the external tool's output, found no additions, printed `Diff source` and exited 0, so a pushed violation passed; with `color.ui always`, the headers carried escape sequences, `Changed files (0)`, PASS, exit 0; with `diff.noprefix true` and a top-level directory named `b`, or `diff.dstPrefix` set, the `+++` label was not the repository path, so the branch and staged scopes' blob readers raised `HEAD_READ_FAILED` or `STAGED_READ_FAILED` for a path that does not exist and blocked a clean push; with `diff.mnemonicPrefix true` the staged scope labelled files `i/`; with `diff.relative true` and a subdirectory as the working directory the paths lost their prefix and every change outside the directory was dropped; with `diff.context 0` the unchanged line a `totem-ignore-next-line` sits on was not in the hunk, so clean code failed; a `diff=<driver>` attribute with a `textconv` showed converted text where the blob readers see the file's bytes, and a failing converter made the diff fatal; `diff.submodule=diff` inlines a submodule's patch under this repository's headers. On a default git config the pins change nothing (measured byte-identical against the unpinned output): seven of the values are git's own defaults, and `--no-textconv` turns off a conversion git applies by default only once a `diff=<driver>` attribute and a converter are configured. One same-class key has no flag: `diff.suppressBlankEmpty` prints an empty context line as an empty string, and the diff parser skipped it, shifting every later line number by one and carrying a `totem-ignore-next-line` across the blank line onto a violation it never named, which then passed; the parser now counts an empty line inside a hunk as the context line git meant. Pinned: core's `getGitDiff`, `getGitDiffStat`, `getGitBranchDiffResult` and `getGitDiffRange`, the cli's `getDiffBetween`, the lockfile-sync gate's two patch reads, the cert-corpus materializer's diff (which pinned two of the flags by hand) and the local extractor's `git log -p`; command modules read the constant through the cli's `git.ts` re-export, since the lint floor keeps static `@mmnto/totem` value imports out of command modules. The list-form reads (`--name-only`, `--name-status`, `--numstat`, `--shortstat`) were measured untouched by every setting and are left as they were. A census test over the three packages' sources reads every array-literal argv (either quote style, balanced brackets, the subcommand after a `-C` pair too) and refuses a `git diff`, or a `git log` with a patch or stat spelling, that does not spread the pins directly after the subcommand, exempting the list forms by flag unless the same argv also asks for a stat; behavioral tests run real git under each setting and assert the readers see the porcelain.
