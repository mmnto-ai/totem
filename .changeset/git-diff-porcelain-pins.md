'@mmnto/cli': patch

Every patch- or stat-producing `git diff` Totem reads, and the two `git log -p` reads, now carry seven porcelain pins directly after the subcommand, `--no-ext-diff --no-textconv --no-color --no-relative --submodule=short --src-prefix=a/ --dst-prefix=b/`, exported from `@mmnto/totem` as `GIT_DIFF_PORCELAIN_ARGS` (mmnto-ai/totem#3113). Before this, every diff `totem lint` and `totem review` graded came from `git diff` with the user's and the repository's git config in force, and the parsers assumed git's default text. Each flag fixes the one output property the parsers assume, measured on git 2.56 in a throwaway repository: with `diff.external` set (difftastic's documented setup), the gate read the external tool's output, found no additions, printed `Diff source` and exited 0, so a pushed violation passed; with `color.ui always`, the headers carried escape sequences, `Changed files (0)`, PASS, exit 0; with `diff.noprefix true` and a top-level directory named `b`, or `diff.dstPrefix` set, the `+++` label was not the repository path, so the branch and staged scopes' blob readers raised `HEAD_READ_FAILED` or `STAGED_READ_FAILED` for a path that does not exist and blocked a clean push; with `diff.mnemonicPrefix true` the staged scope labelled files `i/`; with `diff.relative true` and a subdirectory as the working directory the paths lost their prefix and every change outside the directory was dropped; a `diff=<driver>` attribute with a `textconv` showed converted text where the blob readers see the file's bytes, and a failing converter made the diff fatal; `diff.submodule=diff` inlines a submodule's patch under this repository's headers. On a default git config the pins change nothing (measured byte-identical against the unpinned output on the patch, staged, range, `--stat`, `--shortstat`, `--numstat` and `git log -p` forms): five of the values are git's own defaults, and `--no-ext-diff` and `--no-textconv` turn off behaviours git allows by default that are in force only once an external command or a converter is configured. `--no-relative` arrived in git 2.28 (2020), which is the floor this list sets; below it git refuses the argv as an unknown option, which the gate's patch readers throw, while the stat read, the cli's `getDiffBetween`, the lockfile-sync gate's two reads and the local extractor catch their git errors by design and go quiet, as they already did on any other git failure. Two same-class keys are not pinned: `diff.suppressBlankEmpty` has no flag, so the cure is in the diff parser (it printed an empty context line as an empty string, the parser skipped it, every later line number shifted by one and a `totem-ignore-next-line` above a blank line suppressed the violation below it; the parser now counts an empty line inside a hunk as the context line git meant); and `diff.context 0` hides the unchanged line a `totem-ignore-next-line` sits on, a false FAIL that names its file and line, whose flag `--unified=3` implies `--patch` and would turn the stat read into a patch, so it is disclosed here and not pinned. Pinned: core's `getGitDiff`, `getGitDiffStat`, `getGitBranchDiffResult` and `getGitDiffRange`, the cli's `getDiffBetween`, the lockfile-sync gate's two patch reads, the cert-corpus materializer's diff (which pinned two of the flags by hand) and the local extractor's `git log -p`; command modules read the constant through the cli's `git.ts` re-export, since the lint floor keeps static `@mmnto/totem` value imports out of command modules. The list-form reads (`--name-only`, `--name-status`, `--numstat`, `--shortstat`) were measured untouched by every setting and are left as they were. A census test over the three packages' sources reads every array-literal argv through TypeScript's own parser (so quotes, comments, regex and template literals are read as the compiler reads them; the subcommand after a `-C` pair too; a subcommand held in a variable is not read) and refuses a `git diff`, or a `git log` with a patch or stat spelling, that does not spread the pins directly after the subcommand, exempting `--name-only` and `--name-status` outright (git prints names only whatever else rides with them) and `--numstat` and `--shortstat` unless a patch or stat spelling rides with them; behavioral tests run real git under each setting and assert the readers see the porcelain, and the stat reader is asserted to stay a stat.
