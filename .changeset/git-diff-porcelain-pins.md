Every patch- or stat-producing `git diff` Totem reads, and the two `git log -p` reads, now carry four porcelain pins directly after the subcommand: `--no-ext-diff --no-color --src-prefix=a/ --dst-prefix=b/`, exported from `@mmnto/totem` as `GIT_DIFF_PORCELAIN_ARGS` (mmnto-ai/totem#3113). Before this, every diff `totem lint` and `totem review` graded came from `git diff` with the user's and the repository's git config in force, and the parsers assumed git's default text. Measured on git 2.56 in a throwaway repository: with `diff.external` set (difftastic's documented setup), the gate read the external tool's output, found no additions, printed `Diff source` and exited 0, so a pushed violation passed; with `color.ui always`, the headers carried escape sequences, `Changed files (0)`, PASS, exit 0; with `diff.noprefix true` and a top-level directory named `b`, or `diff.dstPrefix` set, the `+++` label was not the repository path, so the branch and staged scopes' blob readers raised `HEAD_READ_FAILED` or `STAGED_READ_FAILED` for a path that does not exist and blocked a clean push; with `diff.mnemonicPrefix true` the staged scope labelled files `i/`. The four flags override each of those settings, which is what git's own porcelain scripts rely on. Pinned: core's `getGitDiff`, `getGitDiffStat`, `getGitBranchDiffResult` and `getGitDiffRange`, the cli's `getDiffBetween`, the lockfile-sync gate's two patch reads, the cert-corpus materializer's diff (which pinned two of the four by hand) and the local extractor's `git log -p`. The list-form reads (`--name-only`, `--name-status`, `--numstat`, `--shortstat`) were measured untouched by every setting and are left as they were; a census test over the three packages' sources refuses any new patch-producing `git diff` spawn without the pins and exempts the list forms by their flag, and behavioral tests run real git under each setting and assert the readers see the porcelain. No reader's output changes on a default git config.
