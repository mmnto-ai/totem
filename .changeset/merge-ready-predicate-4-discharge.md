The merge-ready gate's predicate 4 (`high-severity-inline`) now reads the DISPOSITION PATH (mmnto-ai/totem#2861). A HIGH/Major bot inline whose `comment.commit.oid` is the head commit no longer counts as "still applying" when its thread is RESOLVED and a disposition NAMES it: a non-bot reply after the root inside the thread, or a non-bot PR-level comment created strictly after the root carrying a `disposition: <root comment id> <verb>` line for that thread — the id being the thread root's REST comment id (the `id=` a `totem resolve-threads` dry-run row prints), the verb the round's word for it (fixed / declined / deferred / nit / extracted / held), which the gate does not validate. The `review-reply` skill's step 2 now ends every round disposition with one such line per bot-rooted thread the round answered, and `totem init` re-stamps the skill. A resolved HIGH that no line after its root names — a bare resolve, however much human chatter follows it, or a round disposition that answered other threads — still applies at every tier, and the deny reason leads with the exact line it looked for, with the thread's own id, so the id survives the bound on `provenance.matched`; with more than one applying it names the first and says a `totem resolve-threads` dry run lists every root id; an unresolved HIGH still denies at predicate 2, so the resolve remains a required step of the path. The id is what closes the class two round-keyed reads left open — any post-dating human comment, then the round's `local-lane:` line — both falsified by the falsification legs on the built core and ruled out by the operator on 2026-09-16. The read is one GraphQL document as before: every thread comment now carries `databaseId`, `createdAt`, `author { __typename }` and the window's `pageInfo`, and the PR-level `comments` connection is paginated in full beside the other three with `author`, `body` and `createdAt` per node — each held to the same strict bar (a missing connection, `pageInfo`, `body`, `createdAt` or `__typename` is an unreadable page, named, never "no evidence"), except the root's `databaseId`, which the schema types nullable: a root without one is a thread no line can name and stays applying, never an unreadable page. A thread with more comments than the ten-comment window is judged on what was read: evidence found inside the window or at PR level discharges it, and a window with none is a fact-side deny at every tier whose reason names the window — never the unevaluable class. Provenance carries `dischargedHigh` and `dischargedBy` (in-thread reply vs PR-level disposition line) beside `highInline`, which now counts what still applies after the discharge, and a discharge prints one audit line on stderr naming the count and the arms. The `totem resolve-threads` evidence rule this otherwise mirrors is deliberately weaker (the verb decides whether a thread MAY be resolved and accepts any post-dating non-bot comment, a trigger included), so a thread the verb resolved on the strength of a trigger stays applying here until a disposition naming it is posted. The fixture README, the four PR captures (re-captured with the final query; mmnto-ai/totem#2871 is the real discharge specimen, its per-thread line posted on the PR under the ruling) and eleven synthetic rows carry the shapes, the negative control in the field shape the legs constructed. (The packages share one fixed changeset group, so every `@mmnto/*` package takes the same minor bump.)
