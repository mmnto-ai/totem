Ship the Gemini CLI session briefing as `.gemini/hooks/SessionStart.cjs` instead of `.js` to stop a silent fail-open (the defect reported on mmnto-ai/totem#2488), closing the scope-out the BeforeTool fix (mmnto-ai/totem#2481) deliberately left open.

The distributed hook body is CommonJS (top-level `require('child_process')` for the `totem describe` / `totem orient --session` briefings). Per mmnto-ai/totem#2558, no `.gemini/settings.json` registration is ever emitted for this hook and Gemini CLI has no filename-convention discovery, so the file only executes via host/plain-node paths — and on a consumer whose `package.json` declares `"type": "module"`, Node resolved the bare `.js` as ESM and threw `ReferenceError: require is not defined` before the briefing emitted anything (reproduced live on totem-status, which had replaced the block with a user-owned ESM rewrite to work around it). A `.cjs` file is CommonJS regardless of the consumer's package `type`, mirroring the load-bearing `.cjs` extension on the Claude-side session hooks and on the Gemini write-time guard. Registering the hook with Gemini CLI itself remains mmnto-ai/totem#2558's scope.

`totem hook install` (which the `prepare` wrapper invokes on every install) and `totem init` now migrate an upgraded consumer: the legacy bounded totem-owned `.gemini/hooks/SessionStart.js` is removed and the `.cjs` successor materialized, under the same ownership gate as the BeforeTool migration, applied at BOTH paths — a user-owned file at the legacy path is skipped untouched; a user-owned file at the successor path blocks the migration even under `--force` (both files stay); a marker-headed drifted-unbounded file at either path is declined until `--force`. Blocks are disclosed on the `totem hook install` summary, the path `prepare` runs on every install. `totem eject` removes both the `.cjs` and the legacy `.js`. `totem doctor --parity` now checks the `.cjs` path; an un-migrated consumer reads as honest-absent `skip`, never as drift.
