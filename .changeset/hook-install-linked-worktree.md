`totem hook install` from a linked git worktree no longer writes the hooks every worktree of the repository shares. The hooks directory git resolves for a linked worktree is the common one, so an install from a worktree on an older branch re-rendered the main worktree's pre-commit, pre-push and post-merge from that branch's templates, silently, with nothing at push time saying so. The installer now reads `git rev-parse --git-dir --git-common-dir` (offline: a `gitdir:` pointer whose target carries a `commondir` file), and from a linked worktree it prints one line naming the main worktree as the owner and skips the write, exit 0, so a consumer's `prepare` script is unaffected; `--force` still writes from a worktree for a user who means it, and rewrites each shared hook whole, trailers included, as `--force` always has; a bare install from the main worktree keeps attested extensions, and the skip line says so. A submodule, whose two dirs are equal, is not a linked worktree. A hooks directory that lies inside the worktree itself (a relative or per-worktree `core.hooksPath`) is written as before, since no other worktree runs it; a hooks directory outside the worktree is treated as shared, so an absolute per-worktree path is skipped too, and `--force` writes it. A bare repository, the one-worktree-per-branch layout with no main working tree, has nothing else to own the shared hooks, so its worktrees write them as before, read from git in the common dir (`rev-parse --is-bare-repository`, so a flag `git sparse-checkout` moved into `config.worktree` still counts). `totem init` (interactive or not), the hidden legacy `totem install-hooks` verb and `--check` are unchanged and still write from a worktree, and the per-checkout session hooks are still regenerated after the skip. The `Git Hooks` row of `totem doctor` is unchanged too: run from a linked worktree it compares the shared hooks against that checkout's own canonical and its `--force` remedy writes that checkout's templates, so run the remedy from the main worktree (mmnto-ai/totem#3122 keeps that row's worktree arm as its own ask). This repository's own `tools/install-hooks.js` takes the same arm, with `TOTEM_HOOKS_FORCE=1` as its force (mmnto-ai/totem#3122).
