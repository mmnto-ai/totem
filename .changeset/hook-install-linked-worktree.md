`totem hook install` from a linked git worktree no longer writes the hooks every worktree of the repository shares. The hooks directory git resolves for a linked worktree is the common one, so an install from a worktree on an older branch re-rendered the main worktree's pre-commit, pre-push and post-merge from that branch's templates, silently, with nothing at push time saying so. The installer now reads `git rev-parse --git-dir --git-common-dir` (offline: a `gitdir:` pointer whose target carries a `commondir` file), and from a linked worktree it prints one line naming the main worktree as the owner and skips the write, exit 0, so a consumer's `prepare` script is unaffected; `--force` still writes from a worktree for a user who means it, and rewrites each shared hook whole, trailers included, as `--force` always has; a bare install from the main worktree keeps attested extensions, and the skip line says so. A submodule, whose two dirs are equal, is not a linked worktree. A hooks directory no other worktree of the repository runs is the worktree's own and is written as before: the installer asks git from every other worktree's root which directory it runs (`rev-parse --git-path hooks`, honoring that worktree's `core.hooksPath`) and compares real locations, so a relative `core.hooksPath` that resolves inside this worktree (`.githooks`) is its own, one that sibling worktrees resolve to a single directory (`../hooks` beside `/repo/main` and `/repo/topic`) is shared, an absolute one in the shared config is shared wherever it lies, and one set in this worktree's own `config.worktree` is its own unless it names a directory another worktree also runs; `--force` writes a shared one. A bare repository, the one-worktree-per-branch layout with no main working tree, has nothing else to own the shared hooks, so its worktrees write them as before, read from git in the common dir (`rev-parse --is-bare-repository`, so a flag `git sparse-checkout` moved into `config.worktree` still counts). `totem init` (interactive or not) and the hidden legacy `totem install-hooks` verb are unchanged and still write from a worktree; `--check` only checks whether hooks are installed and never writes; and the per-checkout session hooks are still regenerated after the skip. The per-worktree test is git's own answer from each other worktree (`worktree list --porcelain`, then `rev-parse --git-path hooks` in each) plus a real-path comparison, so a link inside the worktree to the shared directory is shared and the value's shape is never modelled; the bare read is git's answer in both installers, with the config files as the fallback, read the way git reads them: `core.bare` under `[core]` only, quotes and trailing comments handled, and `config.worktree` only when `config` turns `extensions.worktreeConfig` on. The `Git Hooks` row of `totem doctor` reads the same predicate: run from a linked worktree it says it judged the shared hooks against that checkout's templates and sends every non-pass remedy to the main worktree, since a bare install from there skips and `--force` would write that checkout's templates for every worktree; from the main worktree the row is unchanged. The limits this leaves, a template version stamp in the managed block, a worktree-only override distinct from `--force`, and the arm on `totem init`'s non-interactive branch and the hidden `install-hooks` verb, are mmnto-ai/totem#3125. This repository's own `tools/install-hooks.js` takes the same arm, with `TOTEM_HOOKS_FORCE=1` as its force (mmnto-ai/totem#3122).
