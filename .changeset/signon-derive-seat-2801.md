`totem mail --derive-seat` — the signon step-0 identity probe — plus the managed signon skill reordered to derive the seat before it orients, searches or reads a journal (mmnto-ai/totem#2801; the ruled design and its R1–R4 rulings live in `.totem/specs/2801.md`).

**The flag.** `totem mail --derive-seat` answers the question that precedes every seat-scoped answer — which seat is this session? — and polls nothing. One stdout line, `seat=<id> source=env`, exit 0, when the inherited `TOTEM_SELF_AGENT` names exactly one seat this repo hosts; otherwise a stderr refusal naming the supplied value (or `unset`) and every seat this repo hosts, exit 2 — the same NOT-DERIVED family the poll's unresolved-self arm uses. A repo hosting no seat refuses with the `totem seat add` cure. **Hosts** means the structural set — stated the same way in the flag's help, the wiki reference and the signon skill: `.totem/orchestration/config.json` `host_agents`, else the seat directories, else the cohort map — and that map is now keyed on the **origin repository** rather than the checkout's directory name (see below). The env never contributes to that set: the ambient `TOTEM_SELF_AGENT` is stripped before it is derived, because a hosted set the env feeds cannot refuse the env, and refusing a supplied identity is the one thing this flag exists to do. **This is deliberately asymmetric with `--as <seat>`, which keeps its env fallback when the structural set is empty:** `--as` is the operator's declaration on the command line and the poll serves declarations, while `--derive-seat` corroborates an inherited one — so on a checkout with no seat registration at all the probe refuses while `--as` is served, and the refusal means the repo cannot corroborate you, not that your seat is wrong. A single-seat repo with the env unset therefore still refuses, and a comma list of two still refuses (a duplicated entry, `a,a`, is one identity and is accepted, matching the poll's own normalization); membership folds case and the structural set's spelling is what gets printed. When `host_agents` omits a seat that HAS a present dir, the refusal names that cause (host_agents replaces the dir set, mmnto-ai/totem#2141) and its two cures rather than appending the resolver warning to a verdict that contradicts it. Contradictory with `--as <seat>` and `--all-seats` (exit 2, and the `totem mail` help and the wiki CLI reference both list the contradiction as an exit-2 case): those declare a seat, this one asks which seat was declared.

**Resolver (`@mmnto/totem`): the cohort seat map is keyed on the origin repository.** `COHORT_AGENT_MAP` was keyed on the repo-root basename, so it answered only for checkouts whose DIRECTORY is named after their repository — a per-agent worktree, a second clone, a rename all missed it, and since the orchestration tree is gitignored those checkouts frequently have no seat dirs either, so a repo that plainly hosts seats resolved as hosting none. The key is now the `origin` remote's repository name (`totem` from https or ssh, with or without `.git`, matched case-insensitively since GitHub repo names are), falling back to the basename when there is no origin, no git, or an unparseable URL — so every origin-less checkout behaves exactly as before. The change is not only additive: a checkout whose DIRECTORY is named like a cohort repo but whose origin names another repository — a fork, a mirror, a directory reused for a different project — no longer resolves by that basename, because the origin now answers first. Such a checkout resolves the seats of the repository it is actually a clone of, or none. New core exports: `getOriginRepoName` (reads `git config --local --get remote.origin.url` through core's `safeExec`; never throws, returns `null` for "unknown"), the pure `repoNameFromRemoteUrl` parse, and `envWithoutGitLocation`. That last one is load-bearing: git reads `GIT_DIR` and its siblings before `cwd` and exports them into every hook process, so the read scrubs them from the child's environment (PATH and everything else inherited) and the answer is a function of `cwd` alone — without it, an ambient `GIT_DIR` made a non-repository directory resolve as whatever repository the environment named. The read happens on the map-lookup path only — `TOTEM_SELF_AGENT` and `host_agents` return before it — so an identity-declaring poll spawns no git. Consumers see this as a repo whose seats were previously invisible (`source: 'none'`) now resolving them: on a worktree of a cohort repo, `totem mail` moves from "no self agent resolved" to the mmnto-ai/totem#2204 multi-seat gated shape, and `mail send`'s recipient validation is unchanged (`knownCohortAgents` flattens the whole map and never keyed on a repo). The probe short-circuits before any poll and opens no outbox and no `processed/` dir, which is pinned by a filesystem spy rather than asserted.

**The signon skill** (`SIGNON_SKILL_CONTENT`, re-rendered into `.claude/skills/signon/SKILL.md` and `.agents/skills/signon/SKILL.md`, which stay byte-locked to it) gains three steps and renumbers the rest. Step 0 derives the seat FIRST — read the INHERITED `TOTEM_SELF_AGENT`, use it and never write a different one (a later inline form may only RESTATE it; once overridden the tool can no longer see what was inherited), on an empty env STOP and ask the operator with one reportable failure line instead of guessing, falling back to the crown, or deriving from the repo basename, and on a SET env the probe still refuses, act as if you have no seat and put the refusal in front of the operator — `totem seat add` is never run during a read-only bring-up. Step 1 fixes the order on hook-less seats — assignment mail before orient, before any journal read, before any knowledge search. Step 2 states the kit-first rule with the BLIND-kit marker quoted verbatim: the dispatch subject's literal prefix `BLIND round: ` plus the in-subject deposit clause, with a round in flight while such a dispatch has an unpassed deadline and no deposit received; in flight, signon ends at the kit. Step 3 (the former step 1) now names exactly what the managed SessionStart hook INJECTS — two briefing blocks, `totem describe` and `totem orient --session`, and no journal and no mail; the claim is scoped to injection because the hook also mints a session id, writes a ledger event and spawns sidecar refreshes, none of which reaches the session's context — so journal and mail are derived by hand on every seat instead of assumed present; the hook-seat mismatch fail-closed arm is unchanged. This repo's own `AGENTS.md` Session Start Protocol gains the matching ordering sentence.

Consumer-impact: one new `totem mail` flag (additive — every existing poll path, exit code and output shape is byte-unchanged) and new signon skill text distributed by `totem init`. The managed SessionStart hooks are untouched, and the mmnto-ai/totem#2204 identity gate is untouched.
