`totem mail --derive-seat` — the signon step-0 identity probe — plus the managed signon skill reordered to derive the seat before it orients, searches or reads a journal (mmnto-ai/totem#2801; the ruled design and its R1–R4 rulings live in `.totem/specs/2801.md`).

**The flag.** `totem mail --derive-seat` answers the question that precedes every seat-scoped answer — which seat is this session? — and polls nothing. One stdout line, `seat=<id> source=env`, exit 0, when the inherited `TOTEM_SELF_AGENT` names exactly one seat this repo hosts; otherwise a stderr refusal naming the supplied value (or `unset`) and every seat this repo hosts, exit 2 — the same NOT-DERIVED family the poll's unresolved-self arm uses. A repo hosting no seat refuses with the `totem seat add` cure. Hosted-ness is derived the way `--as` derives it (the structural union of `config.json` `host_agents` > seat dirs ∪ basename map, with any ambient `TOTEM_SELF_AGENT` stripped so the env cannot vouch for itself), and the resolver's own `host_agents`-omits-a-present-seat-dir diagnostic rides every refusal. There is deliberately no fallback arm: a config- or dirs-derived resolution states what the REPO hosts, never what this session was launched as, so the single-seat repo refuses rather than adopting the only seat in sight — implicit identity adoption is the class the flag exists to close. Contradictory with `--as <seat>` and `--all-seats` (exit 2): those declare a seat, this one asks which seat was declared. The probe short-circuits before any poll and opens no outbox and no `processed/` dir, which is pinned by a filesystem spy rather than asserted.

**The signon skill** (`SIGNON_SKILL_CONTENT`, re-rendered into `.claude/skills/signon/SKILL.md` and `.agents/skills/signon/SKILL.md`, which stay byte-locked to it) gains three steps and renumbers the rest. Step 0 derives the seat FIRST — read the INHERITED `TOTEM_SELF_AGENT`, use it and never write a different one (a later inline form may only RESTATE it; once overridden the tool can no longer see what was inherited), and on an empty env STOP and ask the operator with one reportable failure line instead of guessing, falling back to the crown, or deriving from the repo basename. Step 1 fixes the order on hook-less seats — assignment mail before orient, before any journal read, before any knowledge search. Step 2 states the kit-first rule with the BLIND-kit marker quoted verbatim: the dispatch subject's literal prefix `BLIND round: ` plus the in-subject deposit clause, with a round in flight while such a dispatch has an unpassed deadline and no deposit received; in flight, signon ends at the kit. Step 3 (the former step 1) now names exactly what the managed SessionStart hook injects — a `totem describe` block and a `totem orient --session` block, no journal and no mail — so journal and mail are derived by hand on every seat instead of assumed present; the hook-seat mismatch fail-closed arm is unchanged. This repo's own `AGENTS.md` Session Start Protocol gains the matching ordering sentence.

Consumer-impact: one new `totem mail` flag (additive — every existing poll path, exit code and output shape is byte-unchanged) and new signon skill text distributed by `totem init`. The managed SessionStart hooks are untouched, and the mmnto-ai/totem#2204 identity gate is untouched.
