fix(gates): the merge-ready gate wrapper now judges the projection shapes that bypassed it, bounds its whole run by one budget, and carries core's heredoc scanner verbatim (mmnto-ai/totem#2856, mmnto-ai/totem#2857). Under the pilot tier each of these was one lost advisory read; under the strict tier each was a bypass, so both issues were the strict install's precondition. WHAT IS JUDGED NOW: the executable may be spelled `gh`, `gh.exe`, or either behind a path (the basename after the last `/` or `\`, with a case-insensitive `.exe`); a CLOSED table of transparent wrapper programs is stripped with its option grammar before the anchor is read (`sudo`, `env`, `timeout`, `nice`, `nohup`, `command`, `exec`, `time` — which options take a separate operand, how many positionals the word itself eats, whether `--` ends its options), with the assignment strip re-running after each so `env -u X A=1 gh pr merge 5` and `sudo -u root timeout 30 gh pr merge 5` both resolve; `eval` re-tokenizes its operand once (depth 1); a leading redirection is skipped with its file token; and a backtick becomes a segment separator, so the operand of a backtick substitution is a segment of its own (the backtick rides on as a token, so a merge whose TARGET is a substitution still reports `unresolvedTarget` rather than falling back to the current branch). THE BUDGET: the wrapper's deadline is now set at its entry, before stdin is read and before any projection, so the projection's git reads are bounded by what is left of it (10 s ceiling, 250 ms floor, no spawn at all once it is spent) instead of running up to three 10-second reads ahead of a deadline that did not yet exist — where a hung git reached the HOST's hook timeout and a killed hook's exit code is never applied, a fail-open on a fail-closed gate. A spent budget writes `[totem gate-wrapper] the <n> ms budget was spent before gate "<event>" could be evaluated …` and exits 2 at every tier, without spawning the CLI. MINOR: a new hook argument `--budget-ms <n>`, which the installed settings.json line never passes and which can only LOWER the budget (a value below 1000 reads as 1000; above 30000 or unparseable reads as the 30000 default). THE SCANNER: the wrapper's `blankHeredocBodies` was a hand copy of core's `findHeredocs` that had diverged in the fail-open direction — no paren-boundary arms (so a `#` after `(` or after an operator `)` was text and a `<<word` inside it opened a body), a narrower bare-delimiter class (so `<<E:F` read as the prefix `E` and the terminator line never matched), and a double-quote backslash that escaped any next character where core escapes only `$`, backtick, `"`, `\` and newline. Each of those blanked a `gh pr merge` on a later line. It is now a verbatim port of core's walk and its three tables, returning core's spans minus the unused `body`, with the blanker replacing a body with spaces so every offset is preserved; both sites carry a `sync-anchor` comment and an executable parity test holds the two span-for-span equal over the suite's whole command corpus and a seeded 3 000-string fuzz corpus in both bash and PowerShell modes. Core is unchanged apart from that one comment line. The committed `.claude/hooks/gate-wrapper.cjs` is re-scaffolded from the new template. Disclosed and locked as rows, unchanged in the safe direction: a variable executable (`$GH`), an unquoted win32 path (this walk reads POSIX quoting for both tools), `timeout` with no duration, a program not on the closed table (`npx`, `xargs`, `bash -c`), `eval` nested deeper than one level, and the redirection operators whose own separator ends the segment first (`>|`, `2>&1`).
