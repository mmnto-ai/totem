The managed pre-push hook grades the checked-out HEAD's branch-vs-base range, not the working tree. Its lint step runs `totem lint --branch` and its strict-tier shield step runs `totem review --gate --branch`, so both read that diff (`origin/<base>...HEAD`, else the local base) whatever the checkout holds uncommitted. The bare verbs read uncommitted edits first and fell to that scope only on a clean tree, so a dirty checkout had the gate lint and review edits that were not being pushed, skip the commits that were, and record a verdict over the wrong diff (measured on 2.14.0). The lint step probes `totem lint --help` for the flag, as the shield step already probes `totem review --help` for `--gate`, and a CLI without it runs the bare form behind a visible compat line saying it reads uncommitted edits first and the branch diff only on a clean tree; the shield's gate form carries `--branch` under the existing probe, since every CLI that answers it has had the flag since 1.53.9, and its compat form stays bare. `totem lint` on the branch-vs-base scope, whether forced by `--branch` / `--base` or reached by the clean-tree fallback, now reads file content from HEAD (`git show HEAD:<file>`) for everything that reads a file — the AST-context classifier that decides which added lines are code, the ast-grep and tree-sitter rules, a record rule's file-scoped requirement and the Rust test-module exemption — the way `--staged` reads the index, so the bytes judged are the commits being pushed and an unsaved or staged edit can neither hide a pushed violation nor block a clean push; a symlink or a submodule gitlink in the diff is skipped, the reads inherit the environment the diff was produced under, so a hook's `GIT_DIR`, a partial commit's `GIT_INDEX_FILE` and a checkout selected through `GIT_DIR` and `GIT_WORK_TREE` all behave for the reader as they do for the diff, a failed HEAD read, on a rule path or in the AST-context classifier, is `HEAD_READ_FAILED`, never a silent worktree fallback, and `totem review --estimate` follows the same rule. The diff parser now decodes a path as git writes it: a C-quoted header (`"src/caf\303\251.ts"`, which git's default `core.quotepath` writes for any non-ASCII name, and which it always writes for a double quote, a backslash or a control character) is unquoted and its escapes decoded, the tab git appends after any path containing a space is stripped first, quoted or not, and a `diff --git` line with only one side quoted (a rename to or from such a name) is read, so such a file is found, listed, graded and matched by an ignore glob instead of silently skipped; the staged reader, which took the same escaped text, is cured by the same decode. The admission record already carries the resolved scope, so a gate run records `source: branch-vs-base` and the base it diffed. The shield's diff is the branch diff; the full-file context, totem-context hints and ledger annotations an admitted review reads still come from the checkout, report-only under `--gate`. Disclosed: a dirty-tree push from a checkout whose base resolves nowhere now meets the resolver's error the clean-tree path always had, `git fetch origin <base>` when the ref is missing or `git remote set-head origin --auto` (or a local `main` or `master`) when no default branch can be determined, and the hook passes no `--base`; the range is the checkout HEAD's branch diff, not the refs git hands the hook on stdin, so pushing a branch other than the checked-out one still judges the checked-out head (mmnto-ai/totem#2793, the shared mechanism for the lint, review and legs steps); the changed-files listing and the ignore filter still read the `diff --git` line, which git writes without a terminator, so a bare path that itself contains ` b/` is read truncated there and an ignore glob that matches the fragment drops that file from the lint diff (mmnto-ai/totem#3110); every diff the gate reads still trusts the repository's diff config, so an external diff tool or forced colour leaves the gate grading nothing and a renamed `a/` `b/` prefix makes every scope read a path that does not exist, as before this change (mmnto-ai/totem#3113); the `uncommitted` scope's classifier still reads the index before the disk (mmnto-ai/totem#3112); and lint from a subdirectory of the repository loads another rule set (mmnto-ai/totem#3111). An installed hook takes the new form on its next `totem hook install`, which runs on every install where `totem init` wired the managed `prepare` script; a repository with its own hook manager or an appended managed block re-renders only on `totem hook install --force`; `totem doctor` reports the stale hook until then. The committed `tools/pre-push` is regenerated to byte parity. Part of mmnto-ai/totem#3048.
