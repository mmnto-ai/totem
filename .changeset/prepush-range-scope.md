The managed pre-push hook grades the pushed range, not the working tree. Its lint step runs `totem lint --branch` and its strict-tier shield step runs `totem review --gate --branch`, so both read the branch-vs-base diff the push carries (`origin/<base>...HEAD`, else the local base) whatever the checkout holds uncommitted. The bare verbs read uncommitted edits first and fell to that scope only on a clean tree, so a dirty checkout had the gate lint and review edits that were not being pushed, skip the commits that were, and record a verdict over the wrong diff (measured on 2.14.0). The lint step probes `totem lint --help` for the flag, as the shield step already probes `totem review --help` for `--gate`, and a CLI without it runs the bare form behind a visible compat line saying it reads uncommitted edits first and the branch diff only on a clean tree; the shield's gate form carries `--branch` under the existing probe, since every CLI that answers it has had the flag since 1.53.9, and its compat form stays bare. `totem lint` on the branch-vs-base scope, whether forced by `--branch` / `--base` or reached by the clean-tree fallback, now reads file content for AST and file-scoped checks from HEAD (`git show HEAD:<file>`), the way `--staged` reads the index, so the bytes judged are the commits being pushed and an unsaved edit can neither hide a pushed violation nor block a clean push; a failed HEAD read is `HEAD_READ_FAILED`, never a silent worktree fallback, and `totem review --estimate` follows the same rule. The admission record already carries the resolved scope, so a gate run records `source: branch-vs-base` and the base it diffed. The shield's diff is the branch diff; the full-file context, totem-context hints and ledger annotations an admitted review reads still come from the checkout, report-only under `--gate`. Disclosed: a dirty-tree push from a checkout whose base resolves nowhere now meets the resolver's error the clean-tree path always had, `git fetch origin <base>` when the ref is missing or `git remote set-head origin --auto` (or a local `main` or `master`) when no default branch can be determined, and the hook passes no `--base`; and the range is the checkout HEAD's branch diff, not the refs git hands the hook on stdin, so pushing a branch other than the checked-out one still judges the checked-out head (mmnto-ai/totem#2793, the shared mechanism for the lint, review and legs steps). An installed hook takes the new form on its next `totem hook install`, which the managed `prepare` wrapper runs on every install, and `totem doctor` reports the stale hook until then; the committed `tools/pre-push` is regenerated to byte parity. Part of mmnto-ai/totem#3048.
