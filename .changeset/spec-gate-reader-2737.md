The strict spec-gate reader measures what it promises: a body ends only at a same-or-shallower heading, a promised heading matches with one trailing parenthetical dropped or differing, and all nine promised headings are required (mmnto-ai/totem#2737).

**The break it repairs.** The gate required two of the nine headings `totem spec` promises, and its two predicates were both wrong in ways that pulled in opposite directions. Against the seven drafts recorded in `.totem/fixtures/spec-runs-2026-09-02/` — one real run artifact plus six regenerations from the same prompt bytes — the shipped two-heading gate passed 7 of 7 while 3 of them carried a promised section that was empty or unmatched. It was WEAKER than the promise. But extending it naively to all nine would have blocked those same 3 of 7, for reasons that were the reader's semantics rather than the drafts' defects: `hasBodyAfter` ended a section at a heading of ANY level, so `### Technical Approach & Contracts` — opened with a `####` sub-heading, and the longest section each of those drafts wrote — read as EMPTY; and the heading test was exact string equality, so a draft that wrote `### Verification` for `### Verification (MANDATORY — do not skip)` read as MISSING the section it had in fact written. Stricter-than-correct is not a stronger gate; it is a gate that blocks good work and teaches the seat to reach for `--no-verify`.

**What changed — three rules.** A body now ends only at a heading of the SAME OR SHALLOWER level: a deeper heading neither ends it nor counts as one, so a section that opens with a sub-heading is bodied by the text under that sub-heading. A promised heading is matched EXACTLY first, and only if no line matched is it matched tolerantly, with one trailing parenthetical group stripped from BOTH sides — symmetric, so a dropped `(structural constraint)` and a differing `(required)` both match, and level-exact, because the `###` marker is part of the compared string, so `## Problem Statement` never satisfies `### Problem Statement`. And `SPEC_REQUIRED_SECTIONS` is now all nine `### ` lines of the built-in prompt, in prompt order, so the gate asks for what the command asks for. The tolerance is never silent: the pass line carries `· tolerated <promised> ~ <found>` for each heading it accepted that way, so the drift is disclosed on the commit that relied on it rather than absorbed. Trailing whitespace is settled by `trimEnd()` on the exact pass and named nowhere — it is not drift. A tolerantly-matched heading that then blocks for an empty body names both spellings (`has an empty heading <promised> (matched as <found>)`), so the cure is never a string the draft does not contain. And the reader's `safe()` now collapses U+2028 and U+2029 alongside C0 and the DEL/C1 band, which closes the same forged-`[Totem]`-line channel on the pre-existing `anchor.ref`, `createdAt` and artifact-path values as well as on the new one.

**Evidence.** The seven recorded R3 drafts, run through the real hook by a frozen falsifier: 0 blocked after the change, and the 3 that dropped a parenthetical each name the tolerance on their evidence line while the 4 schema-constrained runs match exactly and name none. An exact-match all-nine reader would have blocked 3 of those 7. The positive and negative mutation suite that pins each rule was authored against the final nine-heading contract and run against the UNCHANGED reader before either predicate moved — 4 passed, 7 failed — then frozen and never edited by the commits that fixed the reader, so each case is evidence of a predicate rather than a transcription of the implementation.

**A heading is not a path.** `hasUnrenderableHeadingChar` joins `hasUnrenderableHookChar` in `@mmnto/totem`. The path predicate bans every code point above 0x7e because git C-quotes path bytes above 0x7e in the `diff --name-only` output the hooks' `grep -q` filters read, so a non-ASCII directory name could never match. A required heading meets no path filter — it is rendered by `JSON.stringify` into the reader's JS source and compared in memory — so the heading predicate forbids the five shell/JS-active characters and the control bands (C0, and the DEL/C1 band the reader's `safe()` collapses) while permitting printable non-ASCII. Without it the promise could not include `### Verification (MANDATORY — do not skip)`, a heading the built-in prompt has always asked for. The round-trip through `JSON.stringify`, the single-quoted `node -e` word, `sh` and node is not asserted in prose but executed on every CI OS by the falsifier, which requires the four schema-constrained drafts carrying that heading byte-identical to match on the exact pass.

**MIGRATION.** On the strict tier, a draft written under the built-in prompt that lacks any of the nine promised headings — or carries one with no non-blank, non-heading line before the next heading of the same or shallower level — is now BLOCKED by name (`is missing heading <h>` / `has an empty heading <h>`). The cure is one re-run of `totem spec <issue>`; add `--fresh` if the response is served from cache, because a cached response writes no run artifact. Drafts written under an overridden system prompt, and bound design records, are unaffected: both are held to the looser DOCUMENT shape, which is unchanged in behavior — the level-aware loop is equivalent to the old one on the OR-over-headings shape. Hooks refresh on the next `totem init` or `totem hook install`: a totem-owned hook is drift-repaired in place, and a hook carrying content after its end marker needs `--force` until mmnto-ai/totem#2753 lands. `REFLEX_VERSION` is deliberately NOT bumped — it versions the AGENTS.md / CLAUDE.md reflex block, which this slice does not change, and hook installation runs outside the branch it gates.
