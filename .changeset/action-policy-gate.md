New gate event `action-policy`: a consumer-authored `action-policy.json` in the `totemDir` (`version: 1`, optional `environments[]` of `{ name, branches }`, and `rows[]` of `{ id, action_kind, scope: { paths?, commands? }, environment?, disposition, reason? }` over eight action kinds: `code_edit`, `secret_read`, `db_migration`, `db_data_write`, `deploy_config_change`, `deploy_trigger`, `scheduled_job_change`, `index_rebuild`; every object strict, so an unknown key fails the load) classifies an agent's edits and shell commands, and `totem gate install action-policy` installs it as one PreToolUse entry under the new `Write|Edit|Bash|PowerShell` matcher. The wrapper projects a Write or Edit to `{ tool, path }` and a Bash or PowerShell call to `{ tool, command, platform }`, and passes any other tool or an empty value through without spawning. Path rows use the path-classifier glob dialect against the path made relative to the repository root (repo-relative globs only, at most four `*`; a path outside the repository is never governed); command rows are token-prefix patterns (at most two `*` a token) matched from each statement's program position as the transport shield finds it (past assignments, `env`, `sudo`, `time`, `nohup`, `xargs` and the reserved words), against the program's basename, in every statement including `$( … )` and backtick bodies, with heredoc bodies read as text, so `pnpm db:migrate:prod` matches `CI=1 pnpm db:migrate:prod --force` and `./node_modules/.bin/pnpm db:migrate:prod` and not `pnpm db:migrate:prod-report`. A shell handed a string (`sh -c`, `pwsh -Command`, `cmd /c`, a heredoc on stdin) is a `warn` citing `opaque-shell-string` when the policy has command rows. A row naming an environment applies when the current branch matches that environment's branch globs, every matching environment counting (`currentEnvironments`); the branch is read only when such a row matched, and an unreadable branch skips those rows (`skippedForEnvironment`) and gives `environment-unevaluable`, capped at the skipped rows' own dispositions (a skipped `deny` is `deny` at the strict tier and `warn` at the pilot tier, a skipped `warn` or `display` is `warn`), never an allow. The most severe matching row wins and the verdict cites its id, kind and what matched; a `display` row reports through the warn arm and never blocks. `TOTEM_ACTION_POLICY_OVERRIDE=<row-id>[,<row-id>]`, read from the environment of the process running the hook, turns the verdict into `allow` with one stderr line and `overriddenBy` only when every matching `deny` row is named, and never while a `deny` row naming an environment was skipped. No file allows everything; a corrupt or schema-invalid file fails closed. `totem orient` gains an ACTION POLICY section (only when the file exists, read from the configured `totemDir`) listing the rows and the governed paths among the branch diff and the working tree (untracked files inside new directories included), also in `--json` as `actionPolicy` and as one counts line in the session block, and `totem doctor` gains a sensor-only Action policy row that warns on a corrupt file and never gates. The gate reads statements through the transport shield's own program, heredoc and substitution readers (shared inside core, not duplicated), and core adds `getGitStatusPorcelainRaw`. Disclosed limits: a renamed program, a script the agent wrote and then runs, and anything a shell string contains match no command row; identity is lexical and case-sensitive. Part of mmnto-ai/totem#3106.
