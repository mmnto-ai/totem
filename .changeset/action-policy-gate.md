New gate event `action-policy`: a consumer-authored `action-policy.json` in the configured `totemDir` (`version: 1`, optional `environments[]` of `{ name, branches }`, and `rows[]` of `{ id, action_kind, scope: { paths?, commands? }, environment?, disposition, reason? }` over eight action kinds: `code_edit`, `secret_read`, `db_migration`, `db_data_write`, `deploy_config_change`, `deploy_trigger`, `scheduled_job_change`, `index_rebuild`; every object strict, so an unknown key fails the load) classifies an agent's edits and shell commands, and `totem gate install action-policy` installs it as one PreToolUse entry under the new `Write|Edit|Bash|PowerShell` matcher. The wrapper projects a Write or Edit to `{ tool, path }` and a Bash or PowerShell call to `{ tool, command, platform }`, and passes any other tool or an empty value through without spawning. Path rows use the path-classifier glob dialect against the path made relative to the repository containing the `totemDir` (globs repo-relative, never `../`, `./` or `~`, at most three `*`). Command rows are token-prefix patterns (at most two `*` a token) matched from each statement's program position: past assignments, reserved words and a bounded table of wrappers recognised by basename with their value options (`sudo`, `env`, `nice`, `nohup`, `time`, `xargs`, `command`, `builtin`, `exec`, `busybox`); against the program's basename, a PowerShell backslash basename, a `./`-dropped spelling and a `.exe`/`.cmd` stem; in every statement including `$( … )` bodies, Bash backtick bodies and the substitutions inside an unquoted heredoc, with heredoc text never a statement. A shell handed a string (`eval`; `sh`, `bash`, `zsh`, `dash`, `ksh` with `-c`; `pwsh -Command` and `-EncodedCommand` prefixes; `cmd /c` or `/k`; text fed by a heredoc, a pipe or an input redirection) is a `warn` citing `opaque-shell-string` when the policy has command rows. A row naming an environment applies when the current branch matches its globs, every matching environment counting; an unreadable branch skips those rows and gives `environment-unevaluable`, capped at their own dispositions, never an allow. The most severe matching row wins and the verdict cites it; `display` reports through the warn arm. `TOTEM_ACTION_POLICY_OVERRIDE=<row-id>[,<row-id>]`, read from the environment of the process running the hook, clears the `deny` only when every matching `deny` row is named, and is refused, citing the row, while a `deny` row naming an environment was skipped. No file allows everything; a corrupt file fails closed. `totem orient` gains an ACTION POLICY section and `totem doctor` a sensor-only Action policy row. Every gate's warn, and a pilot-tier deny, now reaches the agent beside the tool result: the shared wrapper prints one PreToolUse `additionalContext` object on stdout when it exits 0 with something to report. Not read, and disclosed: a renamed program, a script the agent wrote and then runs, an interpreter's string, a command reached through another program's arguments, `Invoke-Expression`, `env -S`, a process substitution, a `case` arm and a substitution nested deeper than four. Part of mmnto-ai/totem#3106.
