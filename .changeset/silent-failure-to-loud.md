Silent failure → loud on two of the CLI's own coordination surfaces (mmnto-ai/totem#2685, mmnto-ai/totem#2690).

**`totem mail` — sender faults (mmnto-ai/totem#2685).** A dispatch whose `to:` matches no roster agent is undeliverable to every seat-scoped poll; until now it surfaced only as a `Warning:` on whatever seat happened to poll, and the sender's own poll exited 0. Now, when the dispatch sits in an outbox **this repo hosts for a resolved seat** (path-keyed: the outbox is under `<repoRoot>/.totem/orchestration/`), the poll renders an `Error:` line, carries a structured `senderFaults[]` entry in `--json` (`{kind: 'undeliverable-to', repo, agent, file, to, hint}` — `hint` names the one-recipient rule when the `to:` is a comma list), and **exits `4`** (SENDER FAULT — a new arm: the verdict IS derived; `2` NOT DERIVED wins when both hold). A foreign repo's undeliverable dispatch stays a warning. `ecl-gc` treats an own fault as a red A2.2/A2.4 gate with a named reason (today it was red only by accident of the roster warning riding the gate-armed channel). The core agent-id guard (`@mmnto/totem` `isPathSafeAgentId`) now refuses a comma, so `mail send --to "a,b"` is refused at the front door — the whitespace-free list previously passed and was written. Help, wiki, and the signon skill name the new arm; an `Error:` line names a dispatch basename, so — like a gated poll's warnings — propagate nothing from it.

Minor rather than patch: a new exit arm and a new `--json` key are contract additions scripts can observe (the mmnto-ai/totem#2312 / mmnto-ai/totem#2204 exit-contract precedent class).

**Strict pre-commit gates on spec evidence (mmnto-ai/totem#2690).** The agent-strict pre-commit block gated on `.totem/cache/.spec-completed`, which no CLI path has ever written — every fresh checkout or `totem wt create` worktree ran the command the hook named and was still blocked. The block now passes on what `totem spec` actually writes: a mmnto-ai/totem#2100 run artifact under `.totem/artifacts/runs/` whose top-level `admission.runMetadata.caller` is `spec` (written on every successful run, `--fresh` included), read JSON-aware in the hook via `node -e` — a substring match would have accepted a `review` artifact whose prompt merely quotes the key (the review of this very change would have). The legacy hand-set marker is honored second and named as legacy. The hook prints `[Totem] spec evidence: <artifact> (<createdAt>, N days old)` on every strict commit so a stale pass is visible; a freshness rule is a separate, named follow-up. `tools/pre-commit`, the `hooks.tier` schema doc, and the repo's legacy (unregistered) `.gemini/hooks/BeforeTool.js` reader move in lockstep. Consumers pick up the new hook text on their next `pnpm install` (prepare) or `totem hook install`.
