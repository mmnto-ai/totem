The pinned `hooks.tier` now governs every shell, an AI agent's included, and a new config key `hooks.agentArming` (`'off'` or `'strict'`, absent meaning off) says whether an AI-agent shell arms the strict tier on a standard-tier install (mmnto-ai/totem#3130, designed in one cut with mmnto-ai/totem#3042). Before this cut the managed pre-commit and pre-push hooks armed the strict tier in any shell carrying an agent marker, whatever tier the installer pinned, and the measured outcome in a consumer was declining the hooks altogether, which loses the deterministic lint floor too. The installer renders the key into both enforcement hooks on the line under `TOTEM_HOOK_TIER` (`TOTEM_HOOK_AGENT_ARMING="off"` or `"strict"`), and the hook's agent-detection block runs its marker test only when that line reads `strict`; every downstream arm keeps its one test, `is_agent = 1` or `TOTEM_HOOK_TIER = strict`, so a `--strict` install still arms every shell with or without the key. The marker table gains `TOTEM_SELF_AGENT`, the seat identity every cohort seat exports per shell, which reaches the Kimi, Codex and Gemini CLI seats that export no vehicle variable of their own, and `ANTIGRAVITY_AGENT`, the one vehicle variable a seat reported from its own shell on that thread; `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_AGENT`, `CLAUDE_VERSION` and `CURSOR_TRACE_ID` stay, and `GEMINI_API_KEY` stays excluded. The key is rendered, so an installed hook changes only when it is re-rendered: a bare `totem hook install` (and a `prepare` wrapper's install) re-renders a totem-owned block, `--force` rewrites a hook whole. **A repository that relied on the arming sets `hooks.agentArming: 'strict'` in its tracked config before it re-renders on this cut, or its agents' commits skip the spec-evidence gate and their pushes skip `doctor --strict` and the review gate with nothing at commit or push time saying so** (the legs gate still blocks under `hooks.legsOwed.enforce: 'block'`). `totem doctor` gains a sensor-only **Agent Arming** row: a `warn` when the key is unset on a repository with seats registered under `.totem/orchestration/`, naming the seats and the key; a `pass` naming the value when it is declared; a `pass` when it is unset and no seat is registered. The **Git Hooks** row renders its canonical at the configured arming (absent is off), so a hook rendered at the other value reads as drift with the shape-specific re-render as the remedy, while the tier stays out of that compare as before; `doctor --parity` renders its canonical at the configured arming too and, as before, at the configured tier, with `totem hook install --force` as its remedy. `totem init` asks the question once at config generation on a fresh, non-bare, non-`--strict` interactive run; `totem init --agent-arming` answers it without the prompt; a non-interactive run leaves the key unset and says so; under `--strict` every shell is strict, so the question is skipped and a passed `--agent-arming` is reported as moot. The keys `totem init` declares (`hooks.tier` for `--strict`, `hooks.agentArming` for the arming) now land as one `hooks` object in every generated format, including `totem.config.ts`: the previous `--strict` injection anchored on a closing brace at the end of the file, and the generated file ends with `export default config;`, so it wrote nothing there (the `--pilot` shape, which stays on mmnto-ai/totem#3083); the init summary says what was written, and says so when the generated tail matched no anchor. The CLAUDE.md reflex clause no longer says a Claude Code or Cursor seat gets the strict tier automatically: it names the key, its default, the re-render and the five marker names a shell carries (the two explicit-export aliases, `CLAUDE_CODE_AGENT` and `CLAUDE_VERSION`, stay in the hook's table and out of the prose) (`REFLEX_VERSION` 19). The `hooks.tier` schema comment no longer says agents are enforced at strict regardless of the setting. `hooks.tier` also loses its schema default: a parsed-in default made any `hooks` block at all carry a tier, so a block declaring only `legsOwed`, `shield` or `agentArming` pinned the tier to standard and a bare or forced re-render silently downgraded a hook installed with `--strict` (the downgrade mmnto-ai/totem#2753 ruled against, reached through the key this cut adds and the remedy its doctor row prints; reproduced by the falsification leg before the fold). Now only a declared tier pins one, every reader applies standard when it is absent, the installed hook's own tier survives a re-render under any `hooks` block that declares none, and the exported `TotemConfig` type carries `hooks.tier` as optional. One transition changes direction with it: deleting a declared `tier: 'strict'` while other `hooks` keys remain used to step the hooks down to standard on the next re-render, by that accidental pin; now it leaves them strict, as deleting the whole block always did, and stepping down is a declaration (`tier: 'standard'`, or `totem hook install --standard`). `doctor --parity` still renders its git-hook canonical at the configured tier, standard when none is declared, so a hook installed with `--strict` under a tier-less block reads there as drift that a forced re-render does not clear; its remedy line now says to declare the tier or pass `--standard`, and aligning parity's tier axis with the Git Hooks row's, which reads the installed tier, is left to a follow-up. This repository sets `hooks.agentArming: 'strict'` in its own `totem.config.ts` and ships `tools/pre-commit` and `tools/pre-push` regenerated at that value, so its seats keep the strict arm and a human's shell keeps the standard tier. `docs/wiki/hook-integration.md`, `enforcement-model.md` and `config-reference.md` carry both defaults and the migration.
