A second gate in the gate engine: `transport-shield` (mmnto-ai/totem#2799) — a PreToolUse gate on the **Bash and PowerShell** tools that refuses the known payload-mangling command shapes before the shell sees them, naming the cure in every refusal. `totem gate install transport-shield` (or `--all`, or `totem init --gates=transport-shield`) installs it under a `Bash|PowerShell` matcher beside `freeze-check`'s `Write|Edit` entry.

**The pattern table lives once, in core beside the evaluator** (`packages/core/src/transport-shield.ts`), and every row is a pure function of the payload `{ tool, command, platform }` — no filesystem, no environment; the host passes its own `process.platform`, so the same command yields the same verdict on every machine and a test pins win32 on any runner. Deny rows, in evaluation order, the first to fire wins: `heredoc-escape` (a `<<` / `<<-` body, quoted or bare delimiter, carrying a backslash or a backtick — this transport rewrites both; an unterminated body is read to the end), `msys-body-slash` (win32 + Bash only: a `--body` / `--body=` / `-b` value beginning with `/`, shell-tokenized, so `--body-file` and an `@` body never match), `sed-i-escape` (`sed -i` / `-i.bak` / `--in-place` whose expression carries a backslash, or more than one `-e`, or whose segment carries a newline inside a quoted or `$( … )` operand — the file operand included), `inline-body-escape` (Bash only: a `node -e` / `--eval` / `-p`, `python -c`, `python3 -c` body carrying a backslash or a backtick). Warn rows, consulted only when no deny fired — the contract's first `warn` emitters: `heredoc-oversize` (a body of 4,096 bytes or more; a disclosed heuristic for the harness's dropped-heredoc class) and `msys-rev-path-subshell` (win32 + Bash: a `<rev>:<path>` token inside `$( … )` with no `MSYS_NO_PATHCONV=1` in the command). Heredoc bodies are blanked before the command is tokenized, so a `--body "/x"` inside a heredoc is never read as an argument. Every verdict cites `provenance.source: 'transport-shield pattern table'`, `ref: <row id>` and a bounded, control-character-free `matched` fragment. A shape the table lacks is allowed: the gate enumerates known shapes, and a miss is a corpus gap, never a fail-open of an applicable gate.

**The registry carries each gate's matcher.** New core exports `knownGates()` (`[{ event, matcher }]` in registry order), `gateMatcher(event)` (throws `GATE_INVALID` on an unknown event, never a default), the `GateMatcher` and `GateDefinition` types, and the transport-shield module's `TRANSPORT_SHIELD_EVENT`, `TRANSPORT_PATTERNS`, `transportShieldEvaluator`, `parseTransportShieldPayload`, `HEREDOC_OVERSIZE_BYTES`, `MATCHED_FRAGMENT_MAX` and their types; `knownGateEvents()` now lists both gates. `installGates` takes `{ event, matcher }` pairs resolved from the registry (the `Write|Edit` constant is gone from the installer; `PreToolUseMatcher` gains `Bash|PowerShell`), so each gate installs under its own registry matcher; the upsert stays keyed on the gate's `--event` within that matcher, and an entry a hand edit left under a foreign matcher is left as-is (the upsert's standing contract). Deny rows are scoped to the program they name: every row reads the segment's PROGRAM position (after `VAR=VALUE` assignments and wrappers such as `env`, `sudo`, `time`, `xargs`), so `grep gh -b /x` or `git log --grep sed` is an argument, never an invocation; `msys-body-slash` reads `gh` only (`-b` means something else on `diff`, `curl`, `cp`, `sort`, `du`, `grep`) and honours `MSYS_NO_PATHCONV=1`, the cure it names; `sed-i-escape` reads the expression operand only, never a filename or BSD sed's empty `-i ''` suffix. Heredoc bodies never open a quote for the scanner (an apostrophe in prose does not hide a later heredoc), a terminator is an exact line as bash reads it, and a heredoc inside a `bash -c "…"` operand is a disclosed corpus gap. The scanners read the shell's grammar where a mis-read would desynchronize them: a `#` that begins a word — after an unquoted blank, newline, `;`, `|`, `&`, an opening `(` or an operator `)` — is a comment to the end of the line, discarded without quote processing (an apostrophe in a comment hides nothing; comment text is never an argument), while a `#` that continues a word is not one (`a#b`; `$(x)#a`, where the scanners know that `)` closes a substitution); `$(( … ))` / `(( … ))` arithmetic is skipped (a `<<` shift is not a heredoc); a backslash-quoted delimiter (`<<\EOF`) is a quoted heredoc and a delimiter word is read whole as bash delimits it (`EOF.TXT`, `1EOF`; a `$X` delimiter is read literally, the over-scan direction); an unquoted backslash-newline is a continuation, never the newline `sed-i-escape` refuses; a background `&` ends a segment; `env VAR=x prog` reaches the program; every `--body` / `-b` occurrence is read, not the first; and a `$(` inside single quotes is literal to the warn row. Per ADR-109 the gate, being the registry's first non-exact-match gate, ships a stated false-positive budget — zero denies over the benign corpus in `transport-shield.fold.test.ts` — and the fixture that measures it.

**The distributed PreToolUse wrapper projects a payload per event.** `.claude/hooks/gate-wrapper.cjs` keeps freeze-check's subsystem guardrail behaviourally unchanged (the same exits and messages; the lines now sit inside the event branch) and, under `--event transport-shield`, exits 0 as not-applicable unless the envelope's `tool_name` is `Bash` or `PowerShell` with a non-empty `tool_input.command`, in which case it shells `gate check` with `{ tool, command, platform: process.platform }`; a baked event it cannot project fails closed (exit 2). For every event the wrapper now hands the payload to `gate check` on the child's stdin (`--payload -`, a new form the verb accepts beside the JSON argument) — never argv, whose win32 limit of 32,767 characters a long Bash command exceeds, which failed the spawn and fell into the fail-closed arm with nothing broken; a wrapper installed before this cut keeps passing JSON on argv and still works. The reverse pairing — a wrapper written by this cut against a repo-local `@mmnto/cli` from before it — fails closed (exit 2) on every event, freeze-check included, because the old verb cannot parse `-`; that is the contract for an applicable gate that cannot be evaluated, and the cure is the matching CLI (`gate install` writes the wrapper from the CLI that will evaluate it, so the pairing arises only from a later downgrade of `node_modules`). Because the wrapper is marker-bounded, every `totem gate install` refreshes it in the same run that writes the entry — a consumer never holds the new entry with the old projection. `totem eject` now removes every INSTALLED gate entry whatever its matcher — the needle is the wrapper basename followed by an `--event` token, the shape the installer writes and probes — while a user's own hook entry, even one that mentions the wrapper's basename, survives.

**Not in this cut:** a `gate-config` doctor detector (presence stays attested; a separate slice), gate re-installation from the prepare wrapper (gates remain opt-in repo policy through `gate install` / `init --gates=`), the Gemini BeforeTool template, and any change to the `allow | warn | deny` contract. The positive and negative corpora ride as tests, one assertion per row, and are recorded on the issue before any repo's hook set carries the gate.
