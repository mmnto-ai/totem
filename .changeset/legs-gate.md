The falsification-leg floor gets a reader: `totem legs deposit` records what a leg read, `totem legs gate` answers whether THIS head was read, and the strict pre-push hook blocks a legs-owed push carrying no fresh deposit (mmnto-ai/totem#2698).

**The break it closes.** The review-leg floor was a duty a seat remembered. Nothing read it, so nothing caught it when it was skipped: mmnto-ai/totem#2694's 74-file diff was presented for merge without the leg it owed, and the round in mmnto-ai/totem-strategy#1193 needed six legs over one synthesis — legs 2, 3 and 5 each caught an error the PREVIOUS fold had introduced. A floor that holds only when someone remembers it is not a floor.

**The deposit artifact (`@mmnto/totem`).** `<totemDir>/artifacts/legs/<diffSha>.json`, `schemaVersion` `1.0.0`: `diffSha` (a 40-hex commit, and the file's own name), `readAt` (ISO-8601, the leg's own instant), `findings[]` (`id`, `severity` — `BLOCKING` / `MATERIAL` / `MINOR` — `file`, `line`, `claim`, `counterexample`), `folded[]` (finding ids, a subset of `findings[].id`), and a one-line `verdict`. It is keyed by the READ sha rather than content-addressed, deliberately: the question is _was this head read_, so two legs at one head are the same answer and a rerun supersedes by intent — the writer is create-exclusive and `--replace` DISCLOSES the `readAt` it overwrote instead of silently deduping. Validation runs on the way out, so a writer bug never poisons the store. The loader never throws: a deposit is a hand-editable file a pre-push hook reads on every push, so an unreadable, non-JSON, schema-invalid, newer-major or misnamed file becomes a named one-line `corrupt` row the caller prints, and never masks a valid sibling. Every string that reaches a hook's stdout refuses C0/C1 bytes at the schema boundary, at write and at read alike — a newline in a `verdict` would forge a second `[Totem]` line.

**`totem legs deposit` and `totem legs gate`.** The writer binds a leg's findings file to a head (`totem legs deposit --sha HEAD --from <findings.json>`) and refuses a `--sha` that is not a commit here, a findings file whose `diffSha` disagrees with `--sha`, and an occupied address without `--replace`; a refused write leaves no partial file. `--read-at <iso>` states the leg's own instant, and when neither the flag nor the file carries one the stamp is `now` and the substitution is PRINTED — the resolver breaks ties on that value, so a silently invented instant would be a silently invented ranking. The gate's exit vocabulary is three values: **0** — not owed (no changed path matched, or an empty diff), or owed and answered, with the evidence line naming the deposit, its `readAt` and its counts; **2** — NOT DERIVED (not a git repo, `HEAD` or the base unresolvable), the cause printed; **3** — owed and unanswered, either no deposit at all or none that is ancestor-or-equal of `HEAD`. That block names the BASIS it was owed on (the first five `glob -> file` pairs and a count of the rest), then each stale candidate with its OWN reason — `not an ancestor of head` and `unknown to this repo` are different repairs — and then the cure, `totem legs deposit --sha HEAD --from <findings.json>`. `--advisory` prints every one of those lines and exits 0 for every gate state anyway (a failure before the derivation — an unloadable config, an unknown flag — still exits non-zero). The gate judges `HEAD` and only `HEAD`: there is deliberately no flag for choosing another head, because a caller-chosen head turns a block into a pass.

**The strict pre-push arm.** Under the strict tier — `TOTEM_HOOK_TIER=strict`, or a detected agent — the generated hook BLOCKS on gate exit 3 and, with its own distinct line, on exit 2 and on any other non-zero status, which it names: fail-closed, because "the gate could not derive" is not "the gate passed". The arm is slotted BEFORE the shield block, so a legs-owed push is not first paid for with the slow review gate. A `$TOTEM_CMD` that resolves to a CLI without the verb also blocks on strict, naming the one-command cure; every other tier prints a compat line to stderr instead and passes. For each of the gate's own states the tier changes the exit code and NOTHING else: an advisory run and a strict run of the same state print byte-identical stdout, because the derivation composes those lines once and the flag is applied only to the status.

**Freshness is ancestor-or-equal AND coverage.** A deposit read at X answers for every descendant of X — but ancestry alone let a deposit written against the branch's merge base pass, since it is a real ancestor a commit or two behind whose leg saw none of the diff the push proposes. So a candidate is measured on what it could have READ as well: for an ancestor, the branch diff up to its own head (`git diff --name-only <base>...<diffSha>`, the same base the gate resolved for HEAD) intersected with the owed paths. A candidate covering NONE of them is stale, with its own reason — `covers none of the owed paths (the deposit predates every owed change)` — and an exact match covers everything by construction, costing no git call. Ranking is unchanged: along one lineage a nearer ancestor's diff is a superset of a farther one's, so nearest-first already orders by coverage. The winner's line carries `+N commits since the leg read` and `covers K/N owed paths`; both are disclosure, not a block — the gate never decides that a fold re-arms the leg, doctrine does, and the numbers are what make the question legible. The covariate's `leg:` field carries NEITHER number: v1.2's shape is unchanged, so a round reading only that line still cannot see distance or coverage, and closing that is a format amendment nobody has ruled yet. What the field does guarantee is that it resolves through the same function as the gate, with the same coverage inputs where the scope supplies them, so it never names a deposit the gate would reject.

**The `legs-owed` predicate (`@mmnto/totem`).** `classifyLegsOwed(changedFiles, globs)` returns `{ owed, basis }` — the verdict WITH every `glob -> file` match that produced it — and is pure: no exit codes, no printing, no config, no filesystem, no git. It sits behind the routing seam `totem route` will grow (mmnto-ai/totem#2534), which GROWS this module rather than minting a second classifier that could disagree with the one the hook already trusts. The default `hooks.legsOwed.globs` is the doctrine floor plus the public-copy surfaces plus one contract proxy: `doctrine/**`, `design-tenets.md`, `adr/**`, `proposals/**`, `README.md`, `docs/wiki/**`, `.changeset/**`. A changeset IS the release's compatibility contract, so every releasable slice is owed a leg by derivation rather than by anyone remembering to declare it. A configured list REPLACES the default rather than extending it, and matching uses the same dialect `ignorePatterns` already uses — which means a BARE pattern matches by basename at any depth, so `README.md` owes a leg for every package README, public copy being public copy wherever it sits. A `!`-prefixed glob is an exclusion and wins over any positive it also matched. The gate classifies the UNFILTERED branch diff: `ignorePatterns` and `shieldIgnorePatterns` never hide a path from the floor (they carry index-exclusion semantics, and a repo that keeps `README.md` out of its index must not thereby stop owing a leg for its public copy), and the `[Legs] Diff source:` disclosure says so on every run.

**Covariate line format v1.2.** Both existing `local-lane:` shapes gain an appended ` leg: <sha8> blocking=<n> material=<n> folded=<n>` field, or ` leg: none` when no deposit resolves for `HEAD`. The field is composed BESIDE the core renderers, never inside them, so the v1 verdict text and the v1.1 admission text are byte-unchanged before it. A third head shape, `local-lane: none leg: <sha8> ...`, renders when no verdict and no admission record exists for the lineage but a deposit does — the mmnto-ai/totem#2694 exhibit's cure, a diff presented with no evidence line at all. Consumers keep discriminating on the second token, whose set widens to `<hash8>` / `not-applicable` / `none`. A FOLDED finding counts in both its severity bucket and `folded`, so `blocking=3 folded=3` reads "all addressed" where `blocking=3 folded=0` does not. The amendment is the `.totem/specs/2473.md` v1.2 clause; the format marker, both distributed skill twins and the `init.test.ts` pin moved with it, as v1.1 did.

**`REFLEX_VERSION` 12 to 13.** The managed CLAUDE.md block's step 2 now names the legs gate beside the spec gate — the predicate's config key and the one-command cure — so a consumer's own instructions state the rule its hook enforces.

**MIGRATION — consumers re-run `totem init` (or let the managed hook refresh run).** The reflex block and the pre-push arm both arrive through the existing channel, not a forced upgrade; `totem doctor` reports reflex drift until the block is refreshed. `hooks.legsOwed.globs` is read at RUN time and never rendered into the hook text, so editing the list needs no re-install.

**REACH — the strict arm's live population is small, and the gate judges nothing about findings.** Until mmnto-ai/totem#2706 is ruled, the strict arm fires only on installs that set `TOTEM_HOOK_TIER=strict` and on Cursor seats; this repo's own `tools/pre-push` ships tier `standard`, so this repo's pushes print the advisory line and exit 0. The distributed skill and the CLI's own help say "leg deposit", not the internal spelling this note uses: consumer surfaces carry no review-process vocabulary (mmnto-ai/totem-strategy#619), and a test now holds that line on the templates, both skills and the `totem legs` help text. And the floor is deliberately narrow: the gate asks only whether a leg READ this head. It never judges a finding's severity or its disposition — those counts ride the covariate line for the round to rule.
