fix(hooks): the distributed Gemini `SessionStart.cjs` template emits the `hookSpecificOutput.additionalContext` envelope plus `systemMessage` (mmnto-ai/totem#2613). Interactive Gemini injects SessionStart context only from that envelope — plain exit-0 stdout wraps as `systemMessage`, which the interactive startup consumer never injects — so the briefing was absent from model context in the primary dev flow even once registered. The template now captures both briefing legs (`totem describe` + `totem orient --session`) across **both streams** (the Totem CLI writes its banner and diagnostics to stderr — a stdout-only capture drops the describe leg entirely; the capture therefore now includes lines that previously stayed on inherited stderr, such as the project-local re-exec banner) and emits one payload for both audiences: `additionalContext` is injected as model context, and `systemMessage` renders to the human — as a UI info item on interactive startup (via the hook-system-message path) and on `/clear` (the one surface that has no context injection at all), and as a stderr echo under `gemini -p`. Fail-soft boot is unchanged (exit 0 always; a leg failure carries any partial output plus the unavailable note, which rides both keys). Per-leg budgets drop 30s→20s, cutting the measured worst-case process exit from 60s to 40s against Gemini's 60s default hook timeout (which tree-kills at expiry; post-fix no descendant inherits the hook's own streams). This repo's own tracked `.gemini/hooks/SessionStart.cjs` is regenerated from the current template in the same change — it was byte-in-sync with the old template, and shipping the fix without regenerating it would have introduced silent parity drift on the very seat that boots through it. (The tracked legacy `BeforeTool.js` carries no managed auto-generated marker, so the installer treats it as user-owned; it is registered nowhere, and its disposition rides the deferred arming slice tracked in mmnto-ai/totem#2615.)
