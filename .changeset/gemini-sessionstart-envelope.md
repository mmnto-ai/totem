fix(hooks): the distributed Gemini `SessionStart.cjs` template emits the `hookSpecificOutput.additionalContext` envelope (mmnto-ai/totem#2613). Interactive Gemini ingests SessionStart output only from that envelope — plain exit-0 stdout wraps as `systemMessage`, which the interactive startup consumer never reads, so the briefing was silently dropped in the primary dev flow even once registered. The template now captures both briefing legs (`totem describe` + `totem orient --session`) across **both streams** — the Totem CLI writes its banner and diagnostics to stderr, so a stdout-only capture would drop the describe leg entirely — and emits the envelope **plus** `systemMessage` with the same briefing: `/clear` renders only `systemMessage` (as a UI info item) and `gemini -p` prints it to stderr, so without it those surfaces lose the briefing; the interactive consumer ignores `systemMessage`, so nothing double-renders. The fail-soft boot contract is unchanged (exit 0 always; a totem-unresolvable note rides the envelope so it reaches interactive context). Per-leg budgets drop 30s→20s, cutting the measured worst-case process exit from 60s to 40s against Gemini's 60s default hook timeout (residual, pre-existing: the vendor keys hook completion on stream closure, so a hung grandchild holding a pipe can stall the hook past any inner budget). This repo's own tracked `.gemini/hooks/SessionStart.cjs` is regenerated from the current template in the same change — it was in sync with the old template, and shipping the fix without regenerating it would have introduced silent parity drift on the very seat that boots through it. (The tracked legacy `BeforeTool.js` carries no totem marker, so the installer treats it as user-owned; it is registered nowhere and its disposition rides the mmnto-ai/totem#2478 arming slice.)
