transport-shield: the `msys-body-slash` row now reads the `gh` call inside a command substitution, a backtick, a brace group or after a shell reserved word (the 2026-10-16 trigger was posted from `u1=$(gh pr comment … --body '/gemini review')`, which the row never reached while the gate ran), and also refuses a `gh api` or `gh workflow run` field value (`-F`/`--field` typed, `-f`/`--raw-field` raw, the glued `-fX`) that MSYS would convert: a slash after `=`, `="` or `=(` before the value's first whitespace (`-f body=/gemini review` posts the Git install path exactly as `--body` did; `body=k=/v` too), and a raw `-f key=@/path`. A typed `-F key=@/path` file reference converts to the right Windows path and stays allowed, as does a `=/` after the first whitespace, which MSYS leaves alone. A segment the `MSYS_NO_PATHCONV=1` prefix covers still has its substitution bodies read, because the shell runs them before the prefix applies and an assignment-only statement exports nothing (the `msys-rev-path-subshell` warn row reads the same way now, so its one test that took the outer prefix as reaching the substitution is corrected); an opener escaped with exactly one backslash, or a comment, is text the shell never runs and stays allowed, while two or more backslashes are read as running, because the Bash tool halves each pair before bash sees the command. The shared shell tokenizer is unchanged for backticks (a backtick stays a character and a `;` inside a backtick body still splits the statement, which is fail-closed for every row); the `msys-body-slash` row alone reads backtick bodies, located on the whole command text under two opener pairings (bash's exactly-one-backslash rule and the Bash tool's measured halving rule), either hit a deny, so a gh inside `` u=`gh … --body /x; echo done` `` is read whichever way the transport pairs the backticks. An `export` or `declare -x` statement's own substitutions are read as running before the export applies. The program locator, shared by every row, now reads a program after a shell reserved word, a function header or `time -p`, and the Windows spelling (`gh.exe`, `GH.EXE`, a drive-letter path), so the `sed-i-escape` and `inline-body-escape` rows read those shapes too. The cure line is unchanged (`--body-file`, the PowerShell tool, or `MSYS_NO_PATHCONV=1`). Part of mmnto-ai/totem#2696.
