`totem doctor` gains a `Gemini Workspace Trust` sensor row, and the managed reflex block names the CLI fallback for when the Totem MCP tools are absent (asks 2 and 3 of mmnto-ai/totem#2933).

- **Doctor row.** When the repository's `.gemini/settings.json` declares at least one project-level MCP server, the row reads Gemini CLI's trust file (`~/.gemini/trustedFolders.json`, or where `GEMINI_CLI_TRUSTED_FOLDERS_PATH` or `GEMINI_CLI_HOME` points) and applies Gemini CLI's own rule: of the rules whose folder contains this one (the key, or the key's parent for `TRUST_PARENT`), the longest key wins; paths are realpathed and compared case-insensitively on Windows and macOS. It reports `pass` when the winner trusts the folder, `warn` when no rule matches or the winner is `DO_NOT_TRUST` (Gemini CLI may then suppress MCP servers, so the Totem MCP tools may be absent from a Gemini session; the remediation names `/permissions` in Gemini CLI and `totem search`), and `skip` with its reason when there is no project-level Gemini MCP wiring or the trust file is absent, unreadable, not strict JSON, or unrecognised. User-level and extension MCP servers are not checked. It is a sensor: every result is gate-exempt, so it changes the exit of `doctor --strict` at neither tier. Limit: the rule is read from Gemini CLI 0.61.0's source and may move in a later version; the row parses strict JSON (Gemini CLI also accepts comments) and does not read `GEMINI_RESTRICTED_MODE`, `GEMINI_CLI_TRUST_WORKSPACE`, the `security.folderTrust.enabled` setting (when it is false Gemini CLI trusts every folder) or IDE workspace trust; it declines (`skip`) on anything it does not recognise.
- **Reflex block.** A new Memory Reflexes item: when `search_knowledge` or `add_lesson` is not in the agent's tool list, tell the user and use `totem search "<query>"` and `totem lesson add "<text>"` from the terminal. The reflex version is now 17, so an existing managed block reads as outdated until `totem init` is re-run.

Ask 1 of mmnto-ai/totem#2933 (a line on `describe` / `orient`) is not part of this change.
