`totem doctor` gains a `Gemini Workspace Trust` sensor row, and the managed reflex block names the CLI fallback for when the Totem MCP tools are absent (asks 2 and 3 of mmnto-ai/totem#2933).

- **Doctor row.** When the repository's `.gemini/settings.json` declares at least one project-level MCP server, the row reads Gemini CLI's trust file (`~/.gemini/trustedFolders.json`, or where `GEMINI_CLI_TRUSTED_FOLDERS_PATH`, `GEMINI_CLI_HOME` or `SANDBOX=sandbox-exec` points it) and applies Gemini CLI's own rule: of the rules whose folder contains this one (the key, or the key's parent for `TRUST_PARENT`), the longest key wins; paths are realpathed and compared case-insensitively on Windows and macOS. It reports `pass` when the winner trusts the folder; `warn` when no rule matches, the winner is `DO_NOT_TRUST`, or the trust file is absent under an existing Gemini CLI home (Gemini CLI reads a missing file as an empty one), since Gemini CLI may then suppress MCP servers and the Totem MCP tools may be absent from a Gemini session (the remediation names `/permissions` in Gemini CLI and `totem search`); and `skip` with its reason when there is no project-level Gemini MCP wiring, no Gemini CLI home, or a trust file that is unreadable, not strict JSON, or one Gemini CLI itself rejects when folder trust is on, the default. User-level and extension MCP servers are not checked. It is a sensor: every result is gate-exempt, so it changes the exit of `doctor --strict` at neither tier. Limit: the rule is read from Gemini CLI 0.61.0's source and may move in a later version; the row parses strict JSON (Gemini CLI also accepts comments) and does not read `GEMINI_RESTRICTED_MODE`, `GEMINI_CLI_TRUST_WORKSPACE`, the `security.folderTrust.enabled` setting (when it is false Gemini CLI trusts every folder) or IDE workspace trust. On Windows it declines when this folder's path or any trust-file key contains `~` (a short name, which Gemini CLI resolves natively and the row does not), so one trust-file key containing `~` makes this row decline for every folder on that machine. Relative keys and a relative `GEMINI_CLI_TRUSTED_FOLDERS_PATH` resolve against the doctor's cwd, where Gemini CLI uses its own launch cwd. It declines (`skip`) on anything it does not recognise.
- **Reflex block.** A new Memory Reflexes item: when no `search_knowledge` or `add_lesson` tool is in the agent's tool list (hosts may prefix MCP tool names), tell the user and use `totem search "<query>"` and `totem lesson add "<text>"` from the terminal; in an untrusted Gemini CLI folder the project `GEMINI.md` is not loaded, so that case is signalled by the doctor row, not this item. The reflex version is now 17, so an existing managed block reads as outdated until `totem init` is re-run.
