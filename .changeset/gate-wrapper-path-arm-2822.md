'@mmnto/cli': patch

The gate wrapper now resolves a `totem` CLI from `PATH` when the repo-local `node_modules/@mmnto/cli/dist/index.js` is absent, curing the bootstrap self-block a `Bash|PowerShell`-matched gate had on a fresh clone — the gate applied to the very `pnpm install` / `pnpm build` that would create the repo-local CLI, and to the cure its message named (mmnto-ai/totem#2822). The repo-local pinned CLI stays first and an applicable gate that neither arm can evaluate still fails closed; the no-CLI message now names exits the gate does not block (a terminal outside the harness, or the editor on `.claude/settings.json`), a PATH-arm failure discloses which CLI evaluated (by the PATH entry's basename, never an absolute path), and `totem gate install` prints one line disclosing the property for any gate whose matcher includes `Bash`. The managed session-start notice for a repo whose CLI is not installed now says the same in one sentence: a Bash-matched gate applies to the bootstrap commands and falls back to a `totem` on PATH, so a fresh clone with no `totem` anywhere bootstraps from a terminal outside the harness. The same disclosure prints when a Bash-matched gate is installed through `totem init --gates=`, and the distributed agent-instruction block (`REFLEX_VERSION` 15) gains one item stating the action-gate contract: repo-local CLI first, PATH second, fail closed when neither evaluates.
