'@mmnto/cli': minor
---

Managed git hooks reach consumers that extend them: a bare install rewrites a stale managed block in place when the trailer is an attested `totem:fork` extension, `totem doctor` compares every managed block to the canonical on every install, and neither ever downgrades a strict hook (mmnto-ai/totem#2753).

**The break it repairs.** A repo that appends its own blocks after a hook's end marker never received a managed-hook upgrade through `totem init`, and the doctor said nothing was wrong. Measured on mmnto-ai/liquid-city#1174: `totem init -y` at `@mmnto/cli` 1.123.0 reported "Upgraded reflexes to v13" while both `pre-commit` and `pre-push` kept their 1.121.0 managed text — the file carried five extension blocks after totem's end markers, and mmnto-ai/totem#2406's bounded-ownership rule declines a marker-headed file with any content after its end marker rather than clobber it. The decline is correct; being silent about it, and having no non-destructive way out, was not. `totem doctor` in the same tree printed `All 4 hooks installed`, because its currency compare returned early whenever `totemDir` was `.totem` or undefined — so on the default `totemDir`, which is nearly every repo, the row sensed marker PRESENCE and never compared the block. Presence was never the question that row is asked.

**What changed — the install arm.** `installGitHook` gains one arm, evaluated where the decline happens and before it. When totem owns the file through its end marker and the trailer is ATTESTED, the managed block is regenerated in place and the trailer is carried through byte-for-byte: the file becomes the canonical text plus `existing.slice(endIdx + endMarker.length)` with exactly one leading line terminator removed, so the seam does not gain a blank line on every install. The action reports a summary line distinct from the whole-file drift-repair, naming the carry-through, so a consumer can read from the output that its extension survived. A second bare run is a no-op: the currency compare is the recomposed file, so an attested-trailer hook whose block already equals the canonical is `exists` with no write.

**What attestation means.** The trailer's LEADING COMMENT RUN — every line up to the extension's first command, blank lines skipped — must contain a comment line carrying a full fork marker: `# <!-- totem:fork reason="…" owner="…" attested="…" -->`, parsed by core's `parseForkMarker`, with all three fields non-empty. The run rather than the first line, because that is what consumers actually write: liquid-city's `tools/git-hooks/install.cjs` emits `# [lc] <name> extension` FIRST and the fork marker SECOND, and a first-line rule declines the very datum this slice was built from. Two shapes deliberately do not attest. A marker below the first command vouches for nothing above it. And a marker on a line that is not a comment is a command, not a signature — `rm -rf ./build # <!-- totem:fork … -->` does not buy a rewrite. A BARE `totem:fork` marker, or one missing a field, does not attest either: for the parity detector a bare marker is enough to CLAIM a fork, but carrying a consumer's lines through a rewrite is a maintenance promise, and a promise needs a name, a reason and a date.

**What changed — the doctor arm.** The sensor behind the Git Hooks row (renamed `hooksStaleAgainstCanonical`, since `totemDir` is no longer what it is about) drops the default-`totemDir` early return and resolves the effective dir as the configured value else the installer's own `DEFAULT_TOTEM_DIR`. Every install now compares each hook's managed block — start marker through end marker, the same bounded region the installer owns — against the canonical this `@mmnto/cli` renders. A stale block is a `warn` naming the files and the dir, never a gate. The remediation follows the file's SHAPE, because the four shapes take four different cures: `--force` for a totem-owned whole file or a legacy hook with no end marker, a bare `totem hook install` for an attested extension (with the clause saying the extension is carried through unchanged), and the delete-and-re-append line for any other appended block, whose own lines `--force` would eat. The attested classification is gated on the installer's OWN predicate, so the row never prescribes a bare install the installer would decline — a hook with the user's lines above the block and an attested trailer below takes the appended remedy instead. Mixed shapes get one clause each, and a filename is named once.

**What changed — the enforcement tier.** A bare install with no `--strict` / `--standard` flag and no `hooks.tier` in config now renders each hook at the tier the INSTALLED hook declares (`TOTEM_HOOK_TIER="…"`, read from the managed block only, never from a user line above it), falling back to `standard` when nothing declares one. Both writers do this — `totem hook install` and `totem init`. Without it, keeping a hook current silently re-rendered a `--strict` hook at `standard`: an enforcement downgrade performed by the command the doctor's own stale-block remedy sends people to. This closes the same hazard on the pre-existing mmnto-ai/totem#2138 whole-file drift-repair, not only on the new arm. An explicit flag or a configured `hooks.tier` still wins, in that order. doctor has refused to call a tier difference drift since mmnto-ai/totem#2692 amendment A10; this is the writer-side half of that ruling.

**Which command refreshes which hook.** `totem hook install` rewrites any of the four. `totem init` reaches the arm for `pre-commit` and `pre-push` only: its post-merge step skips on presence (mmnto-ai/totem#2649) and it does not install `post-checkout` at all. Both init rows now report a rewrite — `overwritten` and `block-rewritten` were BOTH silent in init's summary before this slice, which is how "Upgraded reflexes" came to sit beside two hooks that had not moved.

**What did NOT change.** `--force` still overwrites the WHOLE file, trailer included — that is what it is for, and it stays the cure for a legacy hook. An unattested trailer still declines with today's message, byte for byte, and the file is untouched. A configured `totemDir` the installer refuses still leaves the row marker-only, and the bounded drift-repair of mmnto-ai/totem#2138 and the appended-block judgment of mmnto-ai/totem#2692 are unchanged in behavior. Session hooks (`.claude/hooks`, `.gemini/hooks`) are out of scope.

**Regression floor.** The fixtures are the VERBATIM liquid-city extension blocks, transcribed from `install.cjs`'s own string arrays and joined the way it joins them, so the tests exercise the shape a real consumer ships rather than one invented to fit the predicate. The carry-through is pinned by byte equality on both halves — the written block equals the canonical's block, the trailer slice equals the original — on all four hooks, plus a two-block pre-push trailer, a CRLF trailer, an end marker with text on the same line, idempotence on the second run, and `--force` still yielding the canonical alone. Each rejected shape has its own test: unattested, bare marker, `reason` only, a marker below the first command, and a marker on a non-comment line. The tier rule is pinned on both the attested-trailer and owned-whole paths, with the explicit flag winning in both directions. On the doctor side the case the early return hid is a test in both spellings of the default, beside the preamble corner, the mixed-shape remediations, and the could-not-compare arm.

**MIGRATION — none.** No config key, flag, file location or command name moves, and no hook is written that would not have been written before except in the two states this slice is about. Consumers with attested extensions receive the next template on their next bare `totem hook install` or `totem init`; a consumer-side `--force`-then-re-append workaround can be retired. Four things read differently, all of them output:

- **`totem doctor`'s Git Hooks row can now say `warn` where it said `pass`.** A repo whose hooks are behind the running CLI's template gets a stale-block warning instead of `All 4 hooks installed`. The row is a sensor and never gates, including under `--strict`.
- **The doctor's stale-hook message tail changed on every stale case**, from `— the hook reads a tree Totem does not write` to `— the managed block is stale (a newer hook template, or a config change)`, and it now names the canonical's author (`the canonical this @mmnto/cli renders for totemDir '…'`). A script grepping the old tail will not match.
- **The mixed-shape remediation is worded differently**: it composes one clause per shape joined by `; `, naming each group's files, where it previously said `for the rest`. Single-shape remediations are byte-unchanged.
- **New summary lines.** `totem hook install` prints `Drift-repaired <hook> hook (managed block rewritten in place; the attested extension after its end marker carried through unchanged).` for the new action, and `totem init`'s summary gains rows for both rewrite actions where it previously printed nothing.
