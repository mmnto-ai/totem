'@mmnto/cli': minor

Managed git hooks reach consumers that extend them: a bare install rewrites a stale managed block in place when the trailer is an attested `totem:fork` extension, `totem doctor` compares every managed block to the canonical on every install, and neither ever downgrades a strict hook (mmnto-ai/totem#2753).

**The break it repairs.** A repo that appends its own blocks after a hook's end marker never received a managed-hook upgrade through `totem init`, and the doctor said nothing was wrong. Measured on mmnto-ai/liquid-city#1174: `totem init -y` at `@mmnto/cli` 1.123.0 reported "Upgraded reflexes to v13" while both `pre-commit` and `pre-push` kept their 1.121.0 managed text — the file carried five extension blocks after totem's end markers, and mmnto-ai/totem#2406's bounded-ownership rule declines a marker-headed file with any content after its end marker rather than clobber it. The decline is correct; being silent about it, and having no non-destructive way out, was not. `totem doctor` in the same tree printed `All 4 hooks installed`, because its currency compare returned early whenever `totemDir` was `.totem` or undefined — so on the default `totemDir`, which is nearly every repo, the row sensed marker PRESENCE and never compared the block. Presence was never the question that row is asked.

**What changed — the install arm.** `installGitHook` gains one arm, evaluated where the decline happens and before it. When totem owns the file through its end marker and the trailer is ATTESTED, the managed block is regenerated in place and the trailer is carried through byte-for-byte: the file becomes the canonical text plus `existing.slice(endIdx + endMarker.length)` with exactly one leading line terminator removed, so the seam does not gain a blank line on every install. The action reports a summary line distinct from the whole-file drift-repair, naming the carry-through, so a consumer can read from the output that its extension survived. A second bare run is a no-op: the currency compare is the recomposed file, so an attested-trailer hook whose block already equals the canonical is `exists` with no write. The write itself — and with it every GIT-hook write this installer makes: the whole-file and block rewrites, the append onto a user's own hook, the post-merge install, the `<totemDir>/hooks/*.sh` helpers and the pre-push upgrader — goes through core's `writeFileAtomicSync` (mmnto-ai/totem#2620): the bytes land in a same-directory temp, the mode is applied to the temp, and the rename comes last, so an interrupted install leaves the old hook or the new one and never a truncated file. The two append arms are now whole-file replacements (the user's bytes plus ours, their mode kept) for the same reason: an interrupted append leaves a hook truncated mid-block, which git still runs. "The user's bytes" is literal: the hook is read raw, the decoded text serves only the probes (markers, shebang, terminator), the append concatenates bytes, and the block rewrite slices the trailer from the raw file after proving the managed region itself decoded losslessly — so a hook that does not round-trip UTF-8 is appended to with every one of its bytes intact, never with U+FFFD in their place (the mmnto-ai/totem#2620 eject ruling, applied to the installer), and has its block regenerated the same way as long as the managed region itself decodes. When it does not — an ANSI-editor save that turned the template's em dash into a single `0x97` byte — the rewrite has no provable byte offset to slice the extension at, so the install reports `skipped-non-utf8`, leaves the file byte-identical, and `totem doctor` classifies the hook as `non-utf8` with the re-save-as-UTF-8-or-`--force` remedy rather than prescribing the bare install it would decline. The one writer that splices text on both sides of a block, the legacy pre-push upgrader, declines such a hook silently — its ruled posture — and the hook takes `totem hook install --force`. That matters most on the block-rewrite arm, because the trailer is the consumer's own lines and no template can regenerate them. Session hooks (`.claude/hooks`, `.gemini/hooks`) are a separate writer, out of this slice's scope, and still write in place. `totem doctor` reads the installed tier through the installer's own `declaredHookTier`, so the two arms of this slice judge the same bytes at the same tier.

**What attestation means.** The trailer's LEADING COMMENT RUN — every line up to the extension's first command, blank lines skipped — must contain a comment line carrying a full fork marker: `# <!-- totem:fork reason="…" owner="…" attested="…" -->`, parsed by core's `parseForkMarker`, with all three fields non-empty after trimming — a whitespace-only value does not attest. The run rather than the first line, because that is what consumers actually write: liquid-city's `tools/git-hooks/install.cjs` emits `# [lc] <name> extension` FIRST and the fork marker SECOND, and a first-line rule declines the very datum this slice was built from. Two shapes deliberately do not attest. A marker below the first command vouches for nothing above it. And a marker on a line that is not a comment is a command, not a signature — `rm -rf ./build # <!-- totem:fork … -->` does not buy a rewrite. A BARE `totem:fork` marker, or one missing a field, does not attest either: for the parity detector a bare marker is enough to CLAIM a fork, but carrying a consumer's lines through a rewrite is a maintenance promise, and a promise needs a name, a reason and a date.

**What changed — the doctor arm.** The sensor behind the Git Hooks row (renamed `hooksStaleAgainstCanonical`, since `totemDir` is no longer what it is about) drops the default-`totemDir` early return and resolves the effective dir as the configured value else the installer's own `DEFAULT_TOTEM_DIR`. Every install now compares each hook's managed block — start marker through end marker, the same bounded region the installer owns — against the canonical this `@mmnto/cli` renders. A stale block is a `warn` naming the files and the dir, never a gate. The remediation follows the file's SHAPE, because the four shapes take four different cures: `--force` for a totem-owned whole file or a legacy hook with no end marker, a bare `totem hook install` for an attested extension (with the clause saying the extension is carried through unchanged), and the delete-and-re-append line for any other appended block, whose own lines `--force` would eat. The attested classification is gated on the installer's OWN predicate, so the row never prescribes a bare install the installer would decline — a hook with the user's lines above the block and an attested trailer below takes the appended remedy instead. Mixed shapes get one clause each; a filename is named once, except that the legacy note keeps its names when the `--force` clause lists more than the legacy hooks, so the reader can tell which is legacy.

**What changed — the enforcement tier.** The render tier is now resolved as: an explicit `--strict` / `--standard` flag, else `hooks.tier` in config, else the tier the INSTALLED hook declares (`TOTEM_HOOK_TIER="…"`, read from its managed block only, never from a user line above it, and only from an assignment at the start of a line — a comment quoting the assignment does not count), else `standard`. The three live writers apply it — `totem hook install`, `totem init`, and the `<totemDir>/hooks/*.sh` helpers generated for husky / lefthook / simple-git-hooks repos — and it applies under `--force` too, since forcing a rewrite is not itself a tier decision. (`upgradePrePushHookIfNeeded`, the pre-end-marker upgrader, still renders from config alone: its guard skips every template that carries a tier line, so no hook it can reach declares one. That is noted at the call site.) Without that third rung, keeping a hook current silently re-rendered a `--strict` hook at `standard`: an enforcement downgrade performed by the command the doctor's own stale-block remedy sends people to. It closes the same hazard on the pre-existing mmnto-ai/totem#2138 whole-file drift-repair, not only on the new arm.

Note how this sits beside the doctor. doctor compares each hook against a canonical rendered at the tier the INSTALLED hook declares (mmnto-ai/totem#2692 amendment A10), so a `hooks.tier` in config that differs from the hook on disk is NOT reported as drift — but it IS applied on the next install, because config outranks the declaration in the writer's order. The install's summary line is where that change becomes visible.

**Which command refreshes which hook.** `totem hook install` rewrites any of the four. `totem init` reaches the arm for `pre-commit` and `pre-push` only: its post-merge step skips on presence (mmnto-ai/totem#2649) and it does not install `post-checkout` at all. Both init rows now report a rewrite — `overwritten` and `block-rewritten` were BOTH silent in init's summary before this slice, which is how "Upgraded reflexes" came to sit beside two hooks that had not moved.

**What did NOT change.** `--force` still overwrites the WHOLE file, trailer included — that is what it is for, and it stays the cure for a legacy hook. (Its TIER now follows the rule above: with nothing pinned, a forced rewrite of a strict hook stays strict.) An unattested trailer still declines with today's message, byte for byte, and the file is untouched. A configured `totemDir` the installer refuses still leaves the row marker-only, and the appended-block judgment of mmnto-ai/totem#2692 is unchanged. Session hooks (`.claude/hooks`, `.gemini/hooks`) are out of scope.

**Regression floor.** The fixtures are the VERBATIM liquid-city extension blocks, transcribed from `install.cjs`'s own string arrays and joined the way it joins them, so the tests exercise the shape a real consumer ships rather than one invented to fit the predicate. The carry-through is pinned by byte equality on both halves — the written block equals the canonical's block, the trailer slice equals the original — on all four hooks, plus a two-block pre-push trailer, a CRLF trailer, an end marker with text on the same line, idempotence on the second run, and `--force` still yielding the canonical alone. Each rejected shape has its own test: unattested, bare marker, `reason` only, a marker below the first command, and a marker on a non-comment line. The tier rule is pinned on both the attested-trailer and owned-whole paths, with the explicit flag winning in both directions. On the doctor side the case the early return hid is a test in both spellings of the default, beside the preamble corner, the mixed-shape remediations, and the could-not-compare arm.

**MIGRATION — none.** No config key, flag, file location or command name moves, and no hook is written that would not have been written before except in the two states this slice is about. Consumers with attested extensions receive the next template on their next bare `totem hook install` or `totem init`; a consumer-side `--force`-then-re-append workaround can be retired. Five things read differently — four of them output, and one behavior:

- **`totem doctor`'s Git Hooks row can now say `warn` where it said `pass`.** A repo whose hooks are behind the running CLI's template gets a stale-block warning instead of `All 4 hooks installed`. The row is a sensor and never gates, including under `--strict`.
- **The doctor's stale-hook message tail changed on every stale case**, from `— the hook reads a tree Totem does not write` to `— the managed block is stale (a newer hook template, or a config change)`, and it now names the canonical's author (`the canonical this @mmnto/cli renders for totemDir '…'`). A script grepping the old tail will not match.
- **The mixed-shape remediation is worded differently**: it composes one clause per shape joined by `; `, naming each group's files, where it previously said `for the rest`. Single-shape remediations are byte-unchanged.
- **New summary lines.** `totem hook install` prints `Drift-repaired <hook> hook (managed block rewritten in place; the attested extension after its end marker carried through unchanged).` for the new action, and `totem init`'s summary gains rows for both rewrite actions where it previously printed nothing. A second new action, `skipped-non-utf8`, prints `Skipped <hook> hook: its managed block does not decode as UTF-8, so it was left byte-identical …` with the re-save-or-`--force` cure, on both commands; `totem doctor`'s remediation gains the matching re-save clause.
- **Hook writes carry the atomic helper's declared boundaries** (`packages/core/src/fs-atomic.ts`, mmnto-ai/totem#2620), none of which loses a byte of a hook: the hooks directory itself must be writable, not only the hook file; a hook owned by another uid or gid that the process cannot chown fails loud instead of being overwritten in place; after a hard kill mid-write a `<hook>.<pid>-<uuid8>.tmp` can remain beside the hook (inert — git runs exactly-named files only); on Windows a rename over a hook held open by another process fails with the old bytes intact, and the temp suffix adds about twenty characters to an already-long path; and HARD-link identity is not preserved — rename-over replaces the directory entry, so a hook hard-linked from elsewhere (the pattern where symlinks are unavailable) keeps its other name on the OLD content, silently, where the in-place writes this replaces updated every name. Symlink identity is preserved (the helper writes through to the real path). One behavior delta beyond those: a DANGLING symlinked hook, which the old in-place write silently created the target for, now fails loud with ENOENT and the link untouched — remove or re-point the link, then install.
- **A strict hook that a bare install used to re-render at `standard` now stays strict.** On a repo pinning no tier, the pre-commit spec-evidence gate and the pre-push falsification-leg gate resume firing after an install that had been quietly turning them off. That is the fix, not a regression, but it is a behavior change a repo will feel: a push that passed after a bare install may now be gated again.
