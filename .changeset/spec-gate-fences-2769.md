The strict pre-commit spec-gate reader tracks fenced code blocks and no longer counts a bare `####` line as body (mmnto-ai/totem#2769; the two holes the mmnto-ai/totem#2759 round declined as pre-existing).

**The two holes.** A run of `#` with nothing after it was not a heading — so `hasBodyAfter` counted it as body, and a required section followed by a lone `####` line passed the empty-heading check with no content. And the reader tracked no fences, so a draft that quoted the template skeleton inside a fenced block — the shape a draft takes when it pastes the prompt's own headings as an example — read as carrying every section, and the same fenced lines then counted as those sections' bodies. Both admit an empty or quoted skeleton, the class mmnto-ai/totem#2737 measured on the recorded drafts.

**What changed — two rules, one state.** Fences follow CommonMark: a line indented at most three spaces whose first run is three or more backticks or tildes opens a fence (a backtick run only when the rest of the line carries no backtick), the closer is the same character, at least as long, with nothing else on the line, and an unclosed fence runs to the end of the draft — so a twenty-tilde "divider" opens a fence, as it does under CommonMark and GFM. A fence delimiter line is neither a heading, a match candidate, nor body. A line inside a fence is neither a heading nor a match candidate — a promised heading quoted there is not the section it names, and is not body for the section above it either — but any other non-blank fenced line IS body: a section whose only content is a code block is a written section, and the issue's first draft of this rule (fenced lines are not body) would have blocked every mermaid-only `### Execution Flow`. A line consisting only of `#` characters and whitespace, outside a fence, is neither a heading nor body (inside one it is code, and code is body). When a promised heading is missing but a copy of it sits inside a fence — at any indentation, in the exact or the tolerant spelling — the block says so: `is missing heading <h> — it appears only inside a fenced code block opened at line N`, followed by the cure that fits (`that fence is never closed — close it, or write the section outside it` when the fence runs to the end of the draft; `write the section outside the fence` when it is closed). A section emptied by these rules names every rule that emptied it: `has an empty heading <h> — nothing under it counts as body: a promised heading quoted inside a fenced code block; a line of # characters; an empty fenced code block` (whichever apply). The tolerance is symmetric: a different heading that shares a promised heading's parenthetical-stripped form (`### Verification (of the sha256)`) reads as that promised heading inside a fence too — fail-closed, and only heading-shaped lines can match, since every promised heading begins with its `###` marker. So the cure is never a heading the draft contains, and a line the reader refused to count is named as such. Everything else stays: same-or-shallower-level body ends, exact-then-tolerant heading match, the `· tolerated` disclosure, `safe()` on every echoed value, `printf` sinks, the mmnto-ai/totem#2737 suite frozen and green.

**The DOCUMENT arm moves too.** The looser shape an overridden prompt and a bound record are held to (at least one heading with a body) reads through the same fence state: a `# Problem` comment inside a fenced YAML block is not a heading. mmnto-ai/totem#2737 declared that arm unchanged by ITS change; this one changes it, and says so. For a bound record the cure is editing the record — a real heading with a line under it — not re-running `totem spec`.

**MIGRATION.** On the strict tier a draft that carried a promised section only as a lone `####` line, or only inside a fenced block, is now BLOCKED by name (`has an empty heading <h>` / `is missing heading <h> — it appears only inside a fenced code block opened at line N`); the cure is one re-run of `totem spec <issue>` (add `--fresh` if the response is cached). A draft that opened a fence it never closed — a run of three or more tildes or backticks used as a divider, which is a fence opener in Markdown, or a closing fence that repeats the opener's info string (` ```mermaid ` closed by ` ```mermaid `), which under CommonMark does not close it — is blocked the same way, and the reason names the line that opened it. For that second shape a re-run of `totem spec` may reproduce the mistake; the message names the right cure — `close it with a bare closing fence: the same character, at least as long, nothing else on the line`. A bound record whose only headings sit inside fences is blocked as `has no heading with a body`; its cure is editing the record. Hooks refresh on the next `totem init` or `totem hook install`; a totem-owned hook is drift-repaired in place. `REFLEX_VERSION` is not bumped — the reflex block does not change.
