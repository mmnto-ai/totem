### Problem Statement
The spec-first pre-commit gate allows empty or unanchored free-text spec run artifacts to satisfy commit validation. The `totem spec` command must refuse unanchored free-text topics below configured score floors, support `--from <path>` to bind hand-authored records, and the pre-commit hook must enforce both non-empty content and valid anchored run artifacts (issue or record).

### Architectural Context
As ruled in strategy 2026-08-30 (queued behind the seed-20 run of record), `totem spec` must write a contract only when grounded and its output should be used for retrieval input, never the contract itself. Historically, 53/53 spec runs lacked specific anchor metadata beyond a generic 'similarity-only' tag, permitting unanchored topics and empty drafts to slip through the strict pre-commit gate (defined in mmnto-ai/totem#2691).

### Files to Examine
- `packages/cli/src/commands/spec.ts` — Contains the spec generation command, the input resolver, and the run artifact persistence logic.\n- `packages/core/src/artifacts/grounding.ts` — Defines the schemas, types, and summary generator for grounding bundles.\n- `packages/cli/src/commands/install-hooks.ts` — Generates the pre-commit hook script including the latest spec run validation logic.\n- `packages/cli/src/commands/install-hooks.test.ts` — Tests for validating pre-commit hook behavior and artifact parsing.

### Technical Approach & Contracts
1. **Contract Upgrades**: Modify the grounding bundle type and schema inside `packages/core/src/artifacts/grounding.ts` to add a first-class `anchor` property: `{ kind: 'issue' | 'record' | 'free-text'; ref: string; sha256?: string }`. Also, ensure each retrieved item includes its retrieval `score: number` to make floor thresholds evaluatable.\n2. **Spec Resolver Refinement**: In `packages/cli/src/commands/spec.ts`, if resolving a free-text topic with no issue or record anchor, perform vector/knowledge retrieval and check retrieved scores against the floor threshold. If below the threshold, log the floor and highest score, then exit with code 1 without minting any JSON artifact.\n3. **Hand-Authored Record Binding**: Implement `--from <design-record path>`. When used, read the file, compute its SHA256, set the anchor kind to 'record' with the ref and sha256, and save the artifact directly as grounded without invoking the LLM.\n4. **Pre-Commit Gate Upgrade**: In `packages/cli/src/commands/install-hooks.ts`, upgrade the hook logic to find the newest run artifact where `admission.runMetadata.caller === 'spec'`. Check that `grounding.anchor.kind` is either 'issue' or 'record' AND that `output.content` is non-empty by content (at least 120 bytes of non-trivial structured text). Ensure safe navigation to prevent crashes on older, unanchored artifacts.

### Edge Cases & Traps
1. **Older Run Artifacts**: Legacy JSON files in `.totem/artifacts/runs/` will not have `grounding.anchor` defined. The parser in the pre-commit hook must use safe optional chaining (e.g., `run?.grounding?.anchor?.kind`) and treat missing anchors as unanchored/invalid rather than throwing a script execution error.\n2. **Trivial/Refusal Outputs**: A model refusal message or minor whitespace draft satisfies simple length checks. We must check for at least 120 bytes of non-whitespace characters and ensure the anchor restriction restricts these runs to authorized issues/records anyway.\n3. **Hook Parity and Generation**: Modifications to `install-hooks.ts` must match what is validated in `tools-hook-parity.test.ts` and actual shell/node templates to prevent lint/test mismatches.
