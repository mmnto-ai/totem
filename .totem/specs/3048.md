### Problem Statement

In the pre-push hook, `totem review` evaluates uncommitted working-tree modifications instead of the pushed revision range whenever the working tree is dirty. The pre-push hook script and `totem review` invocation must be updated to force the diff source to the pushed commit range (or base-vs-branch range via existing `--push-gate` / explicit diff range options) and record that range in the review verdict artifact.

### Architectural Context

- **Issue #2091 & `DiffForReviewOptions` in `packages/cli/src/git.ts`**: The codebase already introduced `forceBranchVsBase` and explicit `diff` range options to bypass the working-tree fallback chain.
- **Lesson — Strict Tier Hooks (`mmnto-ai/totem#2926`)**: Managed pre-push hooks arm strict tier when run by agents (`CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`). Tests spawning rendered hooks must scrub these environment variables to avoid accidentally executing strict-tier logic in standard-tier test contexts.
- **Lesson — Allowlist child-process calls (`packages/pack-agent-security/test/repo-sweep.test.ts`)**: If any new child-process calls are added to CLI files tracked by security sweep rules, update the pinned call-site count and justification in the sweep test.
- **Lesson — Review Lane Filter Absent Files**: Lane reviews read diffs against file payload filters. Passing an accurate git range ensures review payloads accurately reflect committed code rather than uncommitted artifacts.

### Technical Approach & Contracts

1. **Hook Invocations & Range Detection**:
   - The pre-push git hook receives pushed ref specifications over standard input in the format `<local-ref> <local-sha> <remote-ref> <remote-sha>`.
   - When a commit is pushed, the hook knows the range to evaluate (e.g., `<remote-sha>..<local-sha>`, or if remote is 0000.../new branch, resolve against base `origin/<default-branch>...<local-sha>`).
   - The pre-push hook must either pass `--push-gate` / `--diff <range>` directly to `totem review`, matching how `[Lint]` and `[Legs]` compute the pushed branch diff.

2. **Diff Option Data Contract in `packages/cli/src/git.ts`**:
   Ensure `DiffForReviewOptions` supports forcing push scope or explicit ref ranges and that `getDiffForReview` prioritizes them over uncommitted edits:

   ```typescript
   export interface DiffForReviewOptions {
     staged?: boolean;
     diff?: string; // Explicit ref range e.g. "origin/main...HEAD"
     pushGate?: boolean; // Force branch-vs-base regardless of dirty working-tree
     forceBranchVsBase?: boolean;
   }
   ```

3. **Verdict Provenance Contract**:
   When writing the review verdict/artifact (e.g. `ReviewVerdict` or `.totem/review-*.json`), store the resolved diff source metadata:
   ```typescript
   export interface ReviewVerdictArtifact {
     verdict: string;
     diffSource: 'uncommitted' | 'staged' | 'branch-vs-base' | 'range';
     range?: string;
     filesChanged: string[];
     // ... remaining verdict properties
   }
   ```

### Edge Cases & Traps

- **Pushing a New Branch**: `<remote-sha>` is `0000000000000000000000000000000000000000`. The diff range cannot simply be `<remote-sha>..<local-sha>`; it must fall back to `origin/<defaultBranch>...<local-sha>` using `getDefaultBranch()`.
- **Deleting a Remote Branch**: `<local-sha>` is `0000000000000000000000000000000000000000`. In a branch deletion push, the review step must be skipped altogether.
- **Multiple Ref Lines on Stdin**: A single `git push --all` or multi-ref push emits multiple lines on stdin. The hook must either iterate or aggregate the pushed ranges.
- **Environment Scrubbing in Tests**: Per lesson `mmnto-ai/totem#2926`, any integration test exercising the hook must scrub `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_AGENT`, `CLAUDE_VERSION`, and `CURSOR_TRACE_ID` to prevent unintended strict-tier trigger variations.
- **Security Pack Repo Sweep**: If adding any child-process calls to sweep-monitored files, use `safeExec` where possible, or update `packages/pack-agent-security/test/repo-sweep.test.ts` if direct child_process calls are required.

## Implementation Design

Written after two falsification reads widened the build past the hook. The first triage called the change tactical (hook wiring on existing flags); read 1 showed the hook claim was false for AST rules, and read 2 showed the first repair left the classifier, the span exemption and quoted paths behind. This section records the design those folds carried into `@mmnto/totem` and `@mmnto/cli`; its ride-or-split question was ruled ride by the maintainer on 2026-10-25, before the pull request opened, and read 3's one remaining path shape (a quoted path with a space) was folded after that ruling.

### Scope

The managed pre-push hook grades the pushed range: its lint and strict-shield steps run the branch-vs-base scope, and on that scope every file read `totem lint` makes (ast-grep and tree-sitter rules, the AST-context classifier that decides which added lines are code, a record rule's file-scoped requirement, the Rust test-module exemption) comes from HEAD's blobs; the diff parser decodes paths as git writes them so those reads find the file. It does NOT read the stdin ref list (mmnto-ai/totem#2793, one mechanism for lint, review and legs), does not change what an admitted review's full-file context and hints read (the checkout, report-only under `--gate`), does not repair the changed-files listing's ambiguity for a bare path that itself contains ` b/` (mmnto-ai/totem#3110), does not change the `uncommitted` scope's classifier default (mmnto-ai/totem#3112), and does not touch the legacy synchronous regex dispatcher, which is not on the lint path.

### Data model deltas

- `RunCompiledRulesOptions.readFromHead?: boolean` (cli): set by `lint` and `review --estimate` when the resolved source is `branch-vs-base`; read once per call; `isStaged` wins when both are set. Nothing persists it.
- `TotemErrorCode` gains `HEAD_READ_FAILED` (core): thrown by the HEAD blob reader, rethrown by the AST dispatcher's catch exactly like `STAGED_READ_FAILED`.
- `decodeGitHeaderPath(headerPath): string` (core, exported from `diff-parser.ts`, not from the package index): pure; the trailing tab git appends after any path containing a space is stripped first, quoted or not (read 3), then a quoted header's C escapes decode to UTF-8; a plain path is byte-identical. Used by `extractAddedLines` for `+++` headers and, through the module-local `diffGitDestination` in `sys/git.ts`, by `extractChangedFiles` and `filterDiffByPatterns` for the `diff --git` line, where either side may be quoted on its own.
- `BoundedApplyOptions.readStrategy` (core, existing): the Rust test-span exemption now reads through it when set.
- No new state container, reserved key or sentinel: the blob reader is a closure built inside `runCompiledRules`; the span and file-text caches are the existing per-call maps.

### State lifecycle

Per invocation only. The reader is created after the repo root resolves and dies with the call; the classifier, the regex dispatcher and the AST dispatcher receive the same closure. Nothing crosses a session or request boundary.

### Invariants to lock in via tests

- Under the branch scope the bytes an AST rule, the classifier, a file-scoped requirement and the span exemption judge are HEAD's; a divergent disk or index copy cannot change the verdict in either direction.
- `isStaged` outranks `readFromHead`: the index is read, HEAD never.
- A symlink or a gitlink at HEAD is skipped without a blob read.
- A failed HEAD read on a rule path is `HEAD_READ_FAILED` with the path and ref in the message.
- A C-quoted header decodes to its UTF-8 name in the parser, the changed-files listing, the ignore filter and the helper, with or without git's trailing tab and with either side of a `diff --git` line quoted; a bare spaced path loses only its trailing tab; a plain path is byte-identical.
- The estimator sets `readFromHead` exactly when the source is `branch-vs-base`.
- The hook carries both forced forms, both probes and both compat arms in order, and `tools/pre-push` is byte-identical to the builder.
