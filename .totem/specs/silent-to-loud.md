## Problem Statement

Two silent-failure classes in the CLI's own coordination surfaces, one slice:

1. **mmnto-ai/totem#2685 — a hand-written dispatch whose `to:` resolves to no roster agent is undeliverable and only ever surfaces as a `Warning:` line on whatever seat happens to poll.** The roster sensor exists (`pollMail`, mmnto-ai/totem#2335 → mmnto-ai/totem#2344, `packages/cli/src/commands/mail.ts:934-938`) and is exit-neutral. The sender's own poll exits 0 with its inbox verdict, so the sender believes the round is out. Live specimen: the 2026-08-26 mmnto-ai/liquid-city#1148 blind round, `to: lc-agy, lc-codex, lc-gemini, lc-kimi`. `to:` is single-valued by ADR-098 (`parseHeader` captures one scalar; `DispatchHeader.to` is a string; the `mail mark` ownership check relies on it). **Corrected (review):** the `mail send --to` front door refuses comma lists only when they carry whitespace — `AGENT_ID_UNSAFE_CHAR_PATTERN = /[\p{Cc}\s<>:"|?*]/u` (`packages/core/src/orchestration-resolver.ts:98`) has no comma, so `--to "lc-agy,lc-codex"` passes the hard guard, draws only the advisory unknown-recipient warning (`mail.ts:1508-1519`), and IS written. The send side is in scope after all: one character in one pattern.
2. **mmnto-ai/totem#2690 — the agent-strict pre-commit block gates on `.totem/cache/.spec-completed`, which no CLI path writes.** ~~`totem spec` records `.totem/cache/spec-<hash>.json` (the grounded run artifact)~~ **Struck (review, verified):** `.totem/cache/spec-<hash>.json` is the orchestrator's **TTL response cache** — written only when `ttlSeconds > 0 && !options.fresh` and the LLM returned content (`packages/cli/src/utils.ts:1116, :1403-1420`; body `{timestamp, content}`); a `--fresh` run writes none; a cache hit rewrites nothing. The mmnto-ai/totem#2100 **run artifact** is `.totem/artifacts/runs/<sha256>.json` via `saveRunArtifact` (`utils.ts:1476`), written on every successful synthesis including `--fresh`, gitignored per checkout (`.gitignore:56-58`), with the command tag at `admission.runMetadata.caller` (`"spec"` for `totem spec`; measured on today's worktree run and on 53 of the resident's 157 artifacts). A fresh checkout or `totem wt create` worktree runs the command the hook names and is still blocked; the resident tree passes only because of a hand-made 1-byte marker from 2026-03-29. `tools/pre-commit` is byte-locked to `buildPreCommitHook('standard')` (`tools-hook-parity.test.ts`); `doctor --parity` compares installed hooks against the builders. A second, independent reader of the marker exists: `.gemini/hooks/BeforeTool.js:22` — a pre-managed-era hand file (last touched `a653c523`), **not registered** in `.gemini/settings.json` (only `SessionStart` is) and not what the managed `GEMINI_BEFORE_TOOL` template (`init-templates.ts:487`) emits — inert today, but it names the same wrong evidence.

## Architectural Context

- **Tenet 4 (Fail Loud, Never Drift):** both defects are the sender/committer believing a step succeeded when it did not.
- **Tenet 13 (Sensors, Not Actuators):** rules out having `totem spec` write a flag file (the 2026-03-29 SHA-flag lesson). The hook gates on the data artifact the sensor already emits — now the _right_ artifact.
- **`totem mail` exit-code contract (mmnto-ai/totem#2312, mmnto-ai/totem#2204):** exit 2 is the **NOT-DERIVED** family — the poll cannot assert a verdict. A sender fault is the opposite: the verdict IS derived and rendered, and the seat has a problem beside it. One code carrying both is what a text consumer cannot disambiguate (the `/signon` constant reads exit 2 as "gated — fix identity", the wrong cure for a `to:` typo). **Distinct code** (review, accepted).
- **Channel discipline in `MailPollResult`:** `warnings` is gate-armed in exactly one external consumer — `ecl-gc.ts:689-693` (A2.2 `gateComplete` requires `warnings.length === 0`) and `:819` (A2.4 `verifyComplete`); `notices` never gates. ecl-gc forces `TOTEM_SELF_AGENT` to the compacting seat on both polls, so today an own-outbox undeliverable dispatch reds the janitor's gate via the roster warning. Moving it to a new channel without wiring that channel would silently green the gate — wrong direction. **The new channel is explicitly wired into both ecl-gc gates** (review, accepted).
- **Exposure surface:** an ECL basename is recipient + compressed subject. The `/signon` constant (`init-templates.ts:1943`) and the CLI help (`index.ts:863-865`) already say "propagate nothing from a gated poll's warnings"; the fault line carries the same surface on the same poll and both constants say so in this slice (review, accepted).
- **ADR-098 v0.4 / ADR-106:** `to:` derives from parsed leading frontmatter only (lesson-be5e3e55); one recipient per directed dispatch; `broadcast` is a routing literal.

## Implementation Design (v2)

### Scope

(a) An undeliverable dispatch in an outbox **this repo hosts for a seat in the poll's self-set** becomes a typed, structured sender fault — an `Error:` line, a new `senderFaults[]` channel on `MailPollResult`, a distinct exit code, and a red ecl-gc gate — while a foreign repo's undeliverable dispatch keeps today's warning; comma joins the agent-id hard guard so `mail send --to a,b` is refused at the front door. (b) The strict pre-commit block passes on a mmnto-ai/totem#2100 run artifact whose `admission.runMetadata.caller` is `spec` (legacy `.spec-completed` still honored, named as legacy), prints the evidence it found, and `tools/pre-commit`, the schema doc, and the inert Gemini reader move in lockstep. It will NOT add multi-recipient `to:`, have `totem spec` write any marker, add a freshness _rule_ (a stale pass is now visible, not blocked — the rule stays the follow-up), register or migrate the Gemini hook (mmnto-ai/totem#2481 / mmnto-ai/totem#2487), or change the pre-push hook.

### Data model deltas

- **`MailPollResult.senderFaults: SenderFault[]`** (new, REQUIRED, always present). `SenderFault = { kind: 'undeliverable-to'; repo: string; agent: string; file: string; to: string; hint: string | null }` — structured so `--json` consumers (totem-status inbox counts) can widen it later without a breaking change; the human `Error:` line is rendered FROM it, never stored. Written only by `pollMail`'s roster check; read by `resolveMailExitCode`, `formatTextResult`, `ecl-gc`'s two gates, `--json`. Bounded by `MAX_SCAN`. Invariants: a file that yields a sender fault yields NO roster warning (disjoint by the ownership test); `to` is the control-byte-escaped header value; `hint` is non-null iff `to` contains a comma ("a comma list is not a recipient — ADR-098 `to:` is single-valued; send one directed dispatch per recipient").
- **Ownership test (path-keyed, not label-keyed):** own ⇔ `selfLower.has(slot.agent)` ∧ `slot.outbox` resolves under `<repoRoot>/.totem/orchestration/` (`path.relative` neither absolute nor `..`-prefixed). A same-named seat dir in another workspace repo (residue dir, second checkout, fan-out copy — `doctrine/ecl-discipline.md:270`) stays a warning naming that repo. Two intended consequences stated: under `--all-seats` every host seat's outbox is own (dashboard semantics); on an identity-gated poll the self-set is the union, so the line reads "an outbox this repo hosts" when `selfAgents.source` is not `env`, and "YOUR outbox" only for a single explicit identity.
- **`resolveMailExitCode(): 0 | 2 | 4`** — 4 = SENDER-FAULT (derived verdict + own-outbox fault). 2 keeps its NOT-DERIVED meaning untouched; NOT-DERIVED wins when both hold (nothing to fix in the outbox until identity resolves). `mailCommand`'s return type widens to match; `index.ts:896-897` already propagates any non-zero code.
- **`AGENT_ID_UNSAFE_CHAR_PATTERN`** → `/[\p{Cc}\s<>:"|?*,]/u`. Every agent-id validation (`--to`, `--as`, `--from`, `--agent-id`, ecl-gc) refuses a comma; no cohort seat id carries one.
- Hook: no data model. Evidence = a JSON-aware read (`node -e`, ~50 ms; node is already assumed by the pre-push hook's format-check block) over `.totem/artifacts/runs/*.json`: parse each file, accept only a **top-level** `admission.runMetadata.caller === 'spec'`, report the newest such artifact by its own `createdAt`; else `.totem/cache/.spec-completed` (legacy). **A substring grep was FALSIFIED in review (v3):** the run store is written by every orchestrator caller, and a `review`-caller artifact's `inputBundle` embeds the reviewed diff — so a review of any diff quoting the key (this PR's own test fixture, the wiki line, a CHANGELOG entry) would match, and the strict gate would pass on a review artifact in the very checkout that ships the gate. A substring test cannot tell the artifact's own key from text it carried. The key path is pinned by an executed test; the negative control is an artifact with top-level `caller: "review"` whose `inputBundle` CONTAINS the fixture string.

### State lifecycle

- `senderFaults` is per-poll: created empty in `pollMail`, appended in the single scan loop, returned, never mutated after. ecl-gc reads it from the two polls it already runs (A2.1 discovery, A2.4 verify) — no new state.
- The hook reads filesystem state at commit time and writes nothing (Tenet 13). The run artifact's lifecycle is `totem spec`'s (mmnto-ai/totem#2100); per-checkout, gitignored.

### Invariants to lock in via tests

- An unresolvable `to:` in an outbox hosted by the polling repo for a resolved self seat yields exactly one structured `senderFaults` entry (`kind`, `repo`, `agent`, `file`, verbatim `to`, `hint` iff comma), no roster warning for that file, `resolveMailExitCode === 4`; the text carries an `Error:` line AND the inbox verdict; `--json` carries the object.
- The same dispatch under a same-named seat dir in a FOREIGN workspace repo yields the existing roster warning (naming that repo), no fault, exit 0.
- Identity-gated poll + own fault → the line says "an outbox this repo hosts" and exit is 2 (NOT-DERIVED precedence); `--all-seats` + a peer host seat's fault → exit 4.
- `to: broadcast` and an env/config self agent never fault (existing roster semantics preserved); a clean poll with `senderFaults: []` is exit 0.
- ecl-gc: an own fault makes `gateComplete` false with a `gateReasons` entry naming the file, and makes A2.4 `verifyComplete` false; a foreign warning-only fault does not change today's behavior.
- `isPathSafeAgentId('lc-agy,lc-codex') === false`; `mail send --to "a,b"` is refused with nothing written.
- Executed under `sh` in a temp git repo on a non-protected branch with `CLAUDE_CODE_AGENT=1`: (a) no evidence → exit 1 + `BLOCKED`; (b) `.totem/artifacts/runs/x.json` with `{"admission":{"runMetadata":{"caller":"spec"}},"createdAt":…}` → exit 0 + `spec evidence:` line naming it; (c) an artifact with top-level `caller: "review"` whose `inputBundle.maskedPrompt` CONTAINS the literal fixture string from (b) → exit 1 — the substring-grep falsifier, a mutation-checked negative control; (d) legacy marker only → exit 0 + `(legacy marker)`; (e) an unparseable `.json` beside a valid spec artifact → exit 0 (skipped, not fatal); string assertions keep the `.spec-completed` mention.
- `tools/pre-commit` byte-identical to `buildPreCommitHook('standard')`; the `hooks.tier` schema doc names the run artifact; the signon constant and the mail help name the fault arm and the exit-4 meaning.
