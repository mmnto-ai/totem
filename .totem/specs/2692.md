## 2. The cure — (a), centralized (RECOMMENDED)

- **C1 One resolver.** `resolveHookRenderOptions(cwd, flags?) → { tier, totemDir, fallbackCmd, configPath }` in `install-hooks.ts`: config → `tier = flags ?? config.hooks?.tier ?? 'standard'`, `totemDir = config.totemDir ?? '.totem'`, `fallbackCmd = getFallbackCommand(cwd)`; no config → defaults; config-load failure → defaults + the existing `TOTEM_DEBUG` line. EVERY writer of hook text calls it: `hooksCommand` (`:1108`), `init` (`:1812`, `:1841` — after `:1471`), `installHooksNonInteractive` (`:955`), `upgradePrePushHookIfNeeded` (`:1667`), `generateHookHelpers` (`:277`), and `doctor-parity`'s canonical (`:667`, `:803-814`).
- **C2 Builders take a REQUIRED options object** — `buildPreCommitHook({ tier, totemDir })`, `buildPrePushHook({ fallbackCmd, tier, totemDir })`, `buildHookContent({ fallbackCmd, totemDir })`, `buildPostCheckoutHookContent({ fallbackCmd, totemDir })`. - **C3 Byte-identity at the default.** Rendering at `{ tier:'standard', totemDir:'.totem', fallbackCmd:'pnpm dlx @mmnto/cli' }` produces EXACTLY today's `tools/*` bytes: `tools/*` does not change, no consumer's installed hooks drift on upgrade, and `tools-hook-parity.test.ts` pins `TOTEM_DIR = '.totem'` beside `TIER` on the same stated ground (this repo pins neither).
- **C4 Rendering rules per site** (the value is user-supplied; three quoting regimes): the pre-commit reader gets `const dir = ${JSON.stringify(totemDir + '/artifacts/runs')};` — a JS literal inside the `sh` single-quoted string, so the installer REFUSES a `totemDir` containing `'`, `"`, `\`, a control character or a newline (loud, names the value; the schema refine gains the same clause); `sh` test sites render a shell-quoted literal (`[ -f '<totemDir>/compile-manifest.json' ]` via a `shellQuote`); the two BRE `grep` sites (`:229`, `:265`) render an `escapeBre(totemDir)`; the two BLOCKED messages (`:528,531`) name the rendered dir. - **C5 The TS-side siblings** read `config.totemDir` through the same resolver value: `:282` + `:328-364`, `eject.ts:32,46`, `doctor.ts:2235`, `link.ts:28`.
- **C6 Sensor by construction, plus one always-on line.** `doctor --parity`'s `git-hooks` rows now regenerate at the configured `totemDir`, so a hook rendered for another value is DRIFT with remediation `totem hook install --force` (`doctor-parity.ts:1128-1150`) — no new contract. Changeset: `@mmnto/cli` **minor** (rendered output changes for non-default configs; default bytes identical), `@mmnto/totem` patch (the refine). ## 6. Amendments after the build (2026-08-30, owner-ratified)

The build leg deposited ten deviations and five questions; none was applied silently. Each amendment names the clause it changes and why.

- **A1 (C1) — `totemDir` is read from the REPO-LOCAL config only; a global `~/.totem/` profile yields `.totem`.** The profile `totem init --global` writes declares `totemDir: '.'` (it describes itself), and rendering that into a config-less repo's hooks would point every guard at the checkout root — C3's no-drift invariant would break on every machine with a profile. `tier` keeps its existing any-config precedence; the asymmetry is deliberate: a tier is a preference, a `totemDir` is a path anchored at the config's own directory.
- **A2 (C4) — the refusal set gains `$` and a backtick, and the `sh` sites collapse to ONE plain double-quoted regime** (`[ -f "<totemDir>/…" ]`, the form `tools/*` ships); the JSON literal stays for the reader, `escapeBre` stays for the two `grep` sites. The leg's conditional single-quote regime for `$`/backtick values was correct and byte-preserving; refusing those two characters instead removes a regime and two helpers for a directory name nobody uses. C4's "three quoting regimes" reads as two.
- **A3 (C5) — `link` reads the TARGET repo's own config for its directory name** (`resolveConfigPath(target)` → repo-local `totemDir`, else `.totem`; a global profile never applies), not this repo's: the two sides of a link may configure differently, and the target's config is the only source that knows where its lessons live. `link.ts` names that one directory at the probe, both globs and the summary line.
- **A4 (C6) — `checkGitHooks` compares the totem-owned BLOCK (start marker → end marker), not the whole file, and names the remedy by ownership:** a totem-owned whole file → `totem hook install --force`; a user hook with an APPENDED block → delete the block and re-run `totem hook install` (it re-appends), because `--force` rewrites the whole file (`installGitHook`) and would overwrite the user's own lines. A legacy hook without an end marker is compared whole (conservative). `isTotemOwnedWholeFile` is exported for the sensor.
- **A5 (C1) — the writer list gains `installPostMergeHook`** (two `buildHookContent` sites the record's list omitted); routed through the resolver like every other writer.
- **A6 (C5) — `eject` guards the value it DELETES:** repo-local config only, and a `totemDir` normalising to `''`, `.` or containing `..` falls back to `.totem` — `deleteArtifacts` is `fs.rmSync(path.join(cwd, dir), { recursive: true })`, and the global profile's `.` would have aimed it at the checkout. `.lancedb` stays literal (`lanceDir` is not threaded; out of scope).
- **A7 (C4) — path SHAPES, after the falsification leg (F2.2–F2.5, F6.2, F7.5):** the `@mmnto/totem` schema now normalises `totemDir` (backslashes → `/`, a leading `./` dropped, trailing slashes stripped — `knowledge/` rendered `grep -q 'knowledge//…'`, which never matched, silently) and refuses an empty value (`''` rendered an ABSOLUTE `/artifacts/runs` reader and a `grep -q '/'` that matched everything); `.` stays schema-valid (the global profile's own spelling) but the RENDERER refuses it, a `.`/empty segment, a `..` segment and a leading `-` (a `grep` option), each with the reason; the resolver refuses on the configured value; `generateHookHelpers` refuses BEFORE its `mkdir` (a `..` would have created a directory outside the checkout); `link` refuses a target `totemDir` that names the target itself or escapes it (the glob is written verbatim past a consent prompt that named only the target). The CLI's character predicate and the schema's are pinned identical by a test over every ASCII code point.
- **A8 (C1/C7) — a config that RESOLVES but will not LOAD is a LOUD default (F8.1):** the resolver separates "no config anywhere" (silent defaults — supported) from "config exists, failed to load" (defaults + one `console.error` per resolve naming the file and the failure — `totem init` resolves twice and prints twice; `configError` on the result). Before this the changeset's "refused loudly … by the installer" was false on the actual install path: a refined-out `totemDir` made `loadConfig` throw, the resolver swallowed it, and `.totem/` hooks were installed without a word for a repo whose config said otherwise — the class `519010f4` just closed.
- **A9 (C5) — `eject` names `.totem/prepare.cjs` in its scaffolded roster (F7.4):** init scaffolds the prepare wrapper at `.totem/` regardless of `totemDir` (`PREPARE_SCRIPT_REL`, a sibling hardcode left in place), and the `.totem` directory sweep used to remove it incidentally; under a custom `totemDir` the sweep no longer reaches it. `resolveEjectTotemDir` gains its own test file (F7.2: the destructive-path guard had none).
- **A10 (C6) — the sensor compares on the `totemDir` axis ONLY, and knows a LEGACY hook (F5c/F5d):** the canonical for pre-commit / pre-push is rendered at the tier the INSTALLED hook declares (`TOTEM_HOOK_TIER="…"`), so a hook installed with `--strict` on a repo whose config pins no tier is never reported as `totemDir` drift — the prescribed `--force` would have re-rendered it at standard, a silent enforcement downgrade. A hook with a start marker and NO end marker is `legacy`: compared whole, and its remedy is the one `--force` `install-hooks.ts` prescribes for it (with a back-up-first note) — not the appended-hook "delete the block through its end marker", which was unfollowable and claimed user content that was not there.
