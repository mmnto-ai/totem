## 2. The cure — (a), centralized (RECOMMENDED)

- **C1 One resolver.** `resolveHookRenderOptions(cwd, flags?) → { tier, totemDir, fallbackCmd, configPath }` in `install-hooks.ts`: config → `tier = flags ?? config.hooks?.tier ?? 'standard'`, `totemDir = config.totemDir ?? '.totem'`, `fallbackCmd = getFallbackCommand(cwd)`; no config → defaults; config-load failure → defaults + the existing `TOTEM_DEBUG` line. EVERY writer of hook text calls it: `hooksCommand` (`:1108`), `init` (`:1812`, `:1841` — after `:1471`), `installHooksNonInteractive` (`:955`), `upgradePrePushHookIfNeeded` (`:1667`), `generateHookHelpers` (`:277`), and `doctor-parity`'s canonical (`:667`, `:803-814`).
- **C2 Builders take a REQUIRED options object** — `buildPreCommitHook({ tier, totemDir })`, `buildPrePushHook({ fallbackCmd, tier, totemDir })`, `buildHookContent({ fallbackCmd, totemDir })`, `buildPostCheckoutHookContent({ fallbackCmd, totemDir })`. No defaulted parameter: the compiler forces every call site (a forgotten thread is the H4/H7 class).
- **C3 Byte-identity at the default.** Rendering at `{ tier:'standard', totemDir:'.totem', fallbackCmd:'pnpm dlx @mmnto/cli' }` produces EXACTLY today's `tools/*` bytes: `tools/*` does not change, no consumer's installed hooks drift on upgrade, and `tools-hook-parity.test.ts` pins `TOTEM_DIR = '.totem'` beside `TIER` on the same stated ground (this repo pins neither).
- **C4 Rendering rules per site** (the value is user-supplied; three quoting regimes): the pre-commit reader gets `const dir = ${JSON.stringify(totemDir + '/artifacts/runs')};` — a JS literal inside the `sh` single-quoted string, so the installer REFUSES a `totemDir` containing `'`, `"`, `\`, a control character or a newline (loud, names the value; the schema refine gains the same clause); `sh` test sites render a shell-quoted literal (`[ -f '<totemDir>/compile-manifest.json' ]` via a `shellQuote`); the two BRE `grep` sites (`:229`, `:265`) render an `escapeBre(totemDir)`; the two BLOCKED messages (`:528,531`) name the rendered dir. TS template escaping stays `\${…}` where a shell expansion is meant (`:638,640` precedent).
- **C5 The TS-side siblings** read `config.totemDir` through the same resolver value: `:282` + `:328-364`, `eject.ts:32,46`, `doctor.ts:2235`, `link.ts:28`.
- **C6 Sensor by construction, plus one always-on line.** `doctor --parity`'s `git-hooks` rows now regenerate at the configured `totemDir`, so a hook rendered for another value is DRIFT with remediation `totem hook install --force` (`doctor-parity.ts:1128-1150`) — no new contract. Because `--parity` is pin-gated, `checkGitHooks` gains ONE conditional read: when `config.totemDir !== '.totem'`, regenerate the canonical four via C1 and compare whole-file (the `existing !== hookContent` test `installGitHook` already uses, `:782`) → `warn` + the same remediation. Zero cost on the default.
- **C7 Disclosed behaviour change.** `totem init` and `upgradePrePushHookIfNeeded` start honouring `hooks.tier` from config (they do not today). Changeset: `@mmnto/cli` **minor** (rendered output changes for non-default configs; default bytes identical), `@mmnto/totem` patch (the refine). One truth (config) + a loud line at the break — no shim, no env fallback (project ruling 2026-08-29, mmnto-ai/totem#2691).
- **C8 Docs.** `config-schema.ts:455` (`totemDir` docstring: "rendered into the managed hooks at install; re-run `totem hook install --force` after changing it"), `:593` (the `hooks.tier` docstring names `.totem/artifacts/runs/`), `docs/wiki/config-reference.md:10`.

## 3. The fork — options declined, and why

- **(b) `TOTEM_DIR` env the hooks honour** — declined: nothing sets it (git doesn't, the CLI doesn't, `loadEnv` reads a `.env` this cohort abolished), so on its own it changes no behaviour (H9); it is a SECOND truth beside config; an env value at hook time runs no refine — the `grep` BRE sites become an injection surface (H11); and it cannot reach inside the single-quoted reader without the same rendering work as (a) (H10).
- **(c) document the bound + a doctor sensor** — declined as the cure, ABSORBED as C6/C8: visibility without a fix leaves the strict gate fail-closed forever under a custom `totemDir` (H13), and doctor's hook rows are `warn`-level, so `--strict` would not even block.
- **(d) unlisted — give pre-commit's strict arm a CLI-resolved reader** (the leg's finding): correct-by-construction for the writer/reader join, but it trades the mmnto-ai/totem#2690 property the reader was built for (no CLI boot, ~50 ms, nothing written — Tenet 13) and does nothing for pre-push's `sh`-side guards. Held in reserve: if C4's rendering proves brittle under falsification, (d) is the fallback for the pre-commit arm only.
