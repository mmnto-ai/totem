## Implementation Design

### Scope

Adapt the ADR-112 producer front-end (`totem rule author` → `runRuleAuthor` → ledger → `toCompileFeed` → `compileCandidate`) so an envelope entry carries a **record reference** (`record: .totem/rules/<slug>.rule.yaml`) instead of an inline `dslSource`; derive the certification fixture envelope's preimage source from the record's `examples` by the § Design 10 `(ruleId, ordinal)` key with the CR-blind pair hash as drift sensor; keep the file-level attestations content-addressed to the ingested records' bytes; single-home the two `badExample` readers (Stage 4, doctor) and `totem rule test` onto `examples`; attest `.totem/rules/**/*.rule.yaml` in the compile manifest; file the retrieval-index (chunker) decision as a named issue. It will NOT: populate the live `.totem/compiled-rules.json` from records (the mmnto-ai/totem-strategy#516 populator's edge — authored compiled rules land only in the cert corpus output, as today), widen the 5-row structural-eligibility whitelist, add any record WRITER (no YAML is emitted; Amendment 1 item 2 binds the first writer, named as residue), index records (manifest-only at V1 per the approved design), touch the frozen legacy lesson-compile path or the mined producer, or evaluate `verification_shadow`.

### Data model deltas

- **`AuthoredRuleInputSchema`** (`packages/core/src/spine/authored-rule.ts:159-224`) — carrier change. `dslSource` and `declaredEngine` are REMOVED from the input (see OQ-1); new required `record: string` (repo-relative POSIX path; must resolve inside `<totemDir>/rules/` and end in `.rule.yaml`). `author` · `authoredAt` · `targetDefect` · `structuralClass` · `origin?` unchanged. `positiveFixtures` becomes `RecordFixtureInputSchema[]` min-1: `{ pr, filePath, matchedSpan, contentHash, example: int ≥ 0 }` — the ADR-112 §6 corpus anchor plus an ordinal reference; an inline `preimageSource` is an unknown key (closure). `negativeFixtures` unchanged. Written by authors; read by intake only. Invariant: the entry never carries a mirror of anything the record states (`declaredEngine`, bad/good text) — closure enforces it, and the intake's recursive reserved-key scan (`authored-rule-intake.ts:59-88`) gains `dslSource`, `declaredEngine`, `preimageSource` as named migration rejections (fail-loud message pointing at the record form).
- **`AuthoredRuleRecord`** (`authored-rule.ts`, the intake output) — `dslSource` → `record: { path, contentHash /* sha256-64 of the LF-admitted bytes */, parsed: ParsedRuleRecord }`; `declaredEngine` stays but is DERIVED (`parsed.derivedEngine`, § Design 3), written by intake, read by the whitelist judge + `toCompileFeed`. `parsed` is in-memory only — never hash material (its `contentHash` stands in). `positiveFixtures: AuthoredFixture[]` with derived `preimageSource`.
- **`PreimageSourceSchema`** (`compiler-schema.ts:156-193`) — third discriminated branch `{ kind: 'record', ruleId /* AUTHORED_RULE_ID_RE */, ordinal /* int ≥0 */, pairHash /* sha256-64, CR-blind: ruleExamplePairHash */, badExample, goodExample }`, `.strict()`. Written by intake derivation; read by `evaluatePreimageDifferential` (`preimage-differential.ts:120-169`, evaluated exactly as `lesson`: inline bad/good through `runSmokeGate`). The existing anti-vacuity `superRefine` (`:237-255`) applies post-derivation unchanged.
- **`AuthoringLedgerEntrySchema`** (`authoring-ledger.ts:47-110`) — new optional `record?: { path, contentHash }` (present iff record-carried; `path` informational). **Hash material** (`authoringContentHash`, `:151-175`): `dslSource` → `recordContentHash` (the 64-hex); `path` is NOT material (§ Design 1: a rename changes no identity and must not force re-attestation). Everything else in the material (fixtures incl. the derived `preimageSource`, attestations, `structuralEligibility`, `freezeCommitment`) stays — so an `examples` edit flips the pair hash → flips `contentHash` → ledger `revised`. That IS the § Design 10 "hash-mismatched reference" sensor; no second mechanism.
- **`CompileInputCandidate`** (`candidate-rule.ts`) — `dslSource` becomes optional; new optional `record?: ParsedRuleRecord`. Exactly one carrier: `compileCandidate` throws on both/neither (producer bug, asserted before any parse like the existing ruleId precondition at `compile.ts:135`). Record carrier dispatches to `compileRuleRecord(record, { ruleId, now })` (slice 2); `declaredEngine` binding for records is `compileRuleRecord`'s existing two-sided assert. Mined candidates: unchanged, byte-identical.
- **`CompileManifestSchema`** (`compile-manifest.ts:13-23`) — new optional `records_hash: string` = aggregate sha256 over sorted git-tracked `.totem/rules/**/*.rule.yaml` as `${relPath}\n${lfContent}\n` (the `generateInputHash` method, `:72-102`, generalized by a suffix parameter; `collectMdFiles` → `collectFilesWithSuffix`). Absent `.totem/rules/` ⇒ the empty-set hash (a constant). Written by every `writeCompileManifest` caller (6 sites, C1 census) via one shared `attestRecordsHash(totemDir, repoCwd)`; read by `verify-manifest`.
- **No new module-level state.** No reserved keys or sentinels; the `record` carrier is a separate field, not a tagged `dslSource`.

### State lifecycle

- **Record files** — persistent, author-owned canonical source (Tenet 20 class (a)); never written by anything in this slice. Read per intake invocation through the shipped admit hop (`parseYaml(lf(text))` semantics, `authored-rule-intake.ts:50/:178`) so served exemplar bytes are the LF image the NOQ-1 trial measured.
- **Parsed records / derived preimage sources** — per-invocation values on `AuthoredRuleRecord`; no cache; rebuilt on every `runRuleAuthor` (authoring AND the cert path's `verifyOnly` re-derivation at `spine-authored-cert-corpus.ts:155`).
- **Ledger entries** — append-only, unchanged lifecycle (`appendAuthoringLedgerEntry` `:241-264`); `record.contentHash` is what binds the attestations to the exact ingested bytes (§ Design 1 relocation constraint). Owner of mutation: intake PASS 2 only.
- **`records_hash`** — derived at manifest write, persistent in `compile-manifest.json`, owned by the writer call sites; verifier recomputes.
- No state crosses a lifecycle boundary; no one-shot flags.

### Invariants to lock in via tests

- The record is the only rule carrier on the authored envelope: `dslSource` / `declaredEngine` / inline `preimageSource` are rejected by name at any depth with the migration message, never stripped.
- `declaredEngine` on a record-carried ledger entry always equals the record's `target.type`; it is never read from the envelope.
- Derivation reproduces the record's exemplar byte-exactly on the LF image: a CRLF-authored and an LF-authored copy of the same record yield identical `preimageSource.badExample/goodExample` bytes and an identical `pairHash` (the NOQ-1 P1/P2/P4/P5/P6 classes + the P3 admit consequence).
- Dangling and duplicate ordinals fail loud with rule + ordinal named; a valid reference resolves to exactly `examples[ordinal]`.
- Editing one byte of one example flips the ledger `contentHash` (→ `revised`); renaming the record file does not (path is not material); the cert path's `verifyOnly` refuses a revised record.
- Attestations are bound to record bytes: same envelope + changed record ⇒ `revised` entry; the ledger entry's `record.contentHash` equals sha256 of the LF-admitted bytes ingested.
- `compileCandidate` on a record candidate yields the same `CompiledRule` as calling `compileRuleRecord` directly with the minted `ruleId`; `lessonHash === ruleId`; mined candidates compile byte-identically before/after (existing suites unchanged).
- `evaluatePreimageDifferential` classifies `kind: 'record'` exactly as `kind: 'lesson'` for the same bad/good text; `deriveAuthoredControls` emits only `differential-holds` fixtures, unchanged.
- Stage 4: a record rule whose matched line equals any `examples[i].bad` line classifies `in-scope-bad-example` (the slice-2 pin flips by name); a non-matching line stays `candidate-debt`; legacy rules with `badExample` classify byte-identically.
- `doctor` never raises `no-badExample` for a record rule (it has `examples`); raises it for a legacy rule without `badExample` exactly as today.
- `totem rule test <recordRuleId>` runs every pair through the smoke gate: all `bad` fire ∧ all `good` silent ⇒ PASS; reports per ordinal.
- `records_hash` is path-and-content sensitive: one byte in any record, or a renamed/added/removed record, changes it; the empty-set constant is stable across platforms; `verify-manifest` passes over a record-carrying tree whose manifest was written by the same build.
- Freeze isolation: no file on the `rule-compilation` do-not list is touched; `.totem/compiled-rules.json` and `input_hash` are unaffected by every path in this slice.

### Open questions

> **RULED (operator, 2026-08-22, "greenlight your recs"): OQ-1 → (a) records-only with the fail-loud migration error · OQ-2 → reject duplicate ordinals · OQ-3 → (a) `records_hash` absent is OK iff zero records on disk · OQ-4 → doctor sensor as a follow-up issue, not in this slice.** The build binds to these; the question text below stands as the record.

- **OQ-1 — Carrier replacement vs. additive union.** Should the authored envelope accept ONLY record references (inline `dslSource` becomes a fail-loud migration error), or keep `dslSource` as a second accepted carrier?
  - **Options:** (a) records-only — one authoring surface under closed keys, § Design 13's no-bypass spirit, zero migration cost today (no `authored-rules.yaml` or ledger exists on main or in the cohort; `totem rule author` needs a frozen split artifact, so no external envelope is plausible); ADR-112 intake tests re-pointed at record entries. (b) additive union — smaller diff, all existing tests untouched, but keeps a closed-key-free authoring path alive beside the grammar (the R10 hole) with no consumer to justify it.
  - **Recommendation:** (a), records-only, with the fail-loud migration message as the § Design 6-style migration path.
- **OQ-2 — Duplicate-ordinal strictness.** Two fixtures of one entry referencing the same `examples[i]`.
  - **Options:** reject (the spec's word: "a dangling, duplicate, or hash-mismatched reference fails loud"); or allow (two corpus loci, one synthetic pair).
  - **Recommendation:** reject — spec-literal, reversible, and a second pair is cheap to author.
- **OQ-3 — `records_hash` absence semantics.** The live manifest on main lacks the field and main has no records.
  - **Options:** (a) absent is OK iff zero records on disk; the first record landing forces attestation — no hand-edit of the live manifest now, downstream manifests keep verifying. (b) require the field always — hand-edit `.totem/compile-manifest.json` in this PR (not on the do-not list) and break downstream manifests until they re-write.
  - **Recommendation:** (a).
- **OQ-4 — Unreferenced record files.** A `.rule.yaml` under `.totem/rules/` that no envelope entry ingests.
  - **Options:** intake gate (reject the run — blocks drafting, e.g. the R14 branch's 20 records); `totem doctor` sensor (report, never gate — Tenet 13); nothing.
  - **Recommendation:** doctor sensor as a follow-up issue filed with the index issue (two single-topic issues), not in this slice.
