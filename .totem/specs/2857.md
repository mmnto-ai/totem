### Problem Statement

The merge-ready wrapper template's heredoc blanker (`blankHeredocBodies` inside `CLAUDE_GATE_WRAPPER`, `packages/cli/src/commands/init-templates.ts`) is a hand copy of core's transport-shield scanner (`findHeredocs`, `packages/core/src/transport-shield.ts`) and has diverged from it in the fail-open direction: it has no paren-boundary arms (a `#` after `(` or after an operator `)` is text, so a `<<word` in that text opens a heredoc), and its bare heredoc-delimiter class (`[A-Za-z0-9_.\-\/]`) is narrower than core's `HEREDOC_AT` (`[^\s'"\\<>()|&;]+`), so a delimiter carrying `:`, `*`, `+`, `=`, `,`, `@`, `!` or `~` is parsed as a prefix, the terminator line never matches, and the body blanks to end of input. Either way a `gh pr merge` on a later line runs without a gate read — one lost advisory read under PILOT, a bypass under STRICT. Two further divergences were cured on mmnto-ai/totem#2855; these two are locked there as disclosed-miss rows (`(true)#<<note\ngh pr merge 5`; `cat <<E:F\nbody\nE:F\ngh pr merge 5`). The census leg of 2026-09-19 also observed a third, undisclosed divergence: inside a double-quoted string the template consumes a backslash plus ANY next character, where core consumes it only before `DQ_ESCAPABLE` (`$`, backtick, `"`, `\`, newline); and a difference of output shape — core records spans and blanks by offset with spaces, the template drops body lines.

This issue ships in the same PR as mmnto-ai/totem#2856; the shared Implementation Design (scope, seam, failure modes, verification) is in `.totem/specs/2856.md`. This file carries only the scanner contract.

### Architectural Context

- The wrapper is a dependency-free CommonJS hook; the cohort lesson "Use sync anchors for inlined standalone code" rules that an inlined utility is ported verbatim, labelled with a sync anchor at both sites, and backed by an executable parity test.
- The cure candidates the issue lists, measured (census leg, Node v24.16.0, this machine): **(a) run-time require** — `@mmnto/totem`'s exports map has `import` conditions only and no scanner subpath (`ERR_PACKAGE_PATH_NOT_EXPORTED` for `@mmnto/totem`, `@mmnto/totem/transport-shield` and `@mmnto/totem/dist/transport-shield.js`; mmnto-ai/totem#2851), the package is linked only under `packages/cli/node_modules/` in this monorepo, so the hook would have to probe install layouts and fail closed on every one it does not know — rejected for this PR, re-openable when 2851 lands a `require` condition and a subpath; **(b) build-time generation** — no generator exists, and the template literal's escaping makes a spliced segment its own hazard — rejected; **(c) verbatim port + parity lock** — ruled.
- `findHeredocs` is exported from `packages/core/src/transport-shield.ts` (not re-exported from core's index; its only in-repo importer is `transport-shield.fold.test.ts`). Its shape: `findHeredocs(command: string, opts: { powershell?: boolean } = {}): HeredocSpan[]` with `HeredocSpan = { delimiter, quoted, stripTabs, body, unterminated, bodyStart, bodyEnd }`. Core's blanker (`blankHeredocBodies(command, spans)`, module-private) replaces each `[bodyStart, bodyEnd)` with spaces, preserving offsets.

### Technical Approach & Contracts

1. **The port.** The template's scanner becomes `findHeredocSpans(command, powershell)`: a line-for-line JavaScript port of core's `findHeredocs` and its helpers (`HEREDOC_AT`, `DQ_ESCAPABLE`, `WORD_BOUNDARY`, `skipArithmetic`), same arm order, same state (`pending`, `parens`, `inSingle`, `inDouble`, `boundary`), same return shape minus `body` (the wrapper never needs the text). `blankHeredocBodies(command, powershell)` keeps its signature and becomes a span blanker: for each span, replace `command.slice(bodyStart, bodyEnd)` with the same number of spaces — core's shape, offsets preserved. The downstream tokenizer (`ghPrMergeArgvs`) already treats runs of spaces as one boundary, so the change of blanking shape is invisible to it; the existing heredoc rows in the suite prove that.
2. **Sync anchors.** A comment line `// sync-anchor: findHeredocs-scanner-upstream` above core's `findHeredocs` and `// sync-anchor: findHeredocs-scanner-downstream (packages/core/src/transport-shield.ts findHeredocs; the parity test in gate-install.test.ts is the lock)` above the template's port. No code in core changes.
3. **The parity lock** (in `gate-install.test.ts`, a new `describe`): load the rendered template's exports (write `CLAUDE_GATE_WRAPPER` to a temp `.cjs`, `createRequire(import.meta.url)(thatPath)` — the export seam in `2856.md` § E), import core's `findHeredocs` by relative path (`../../../core/src/transport-shield.js`, the exemplar's pattern), and assert deep-equal span lists (`delimiter, quoted, stripTabs, unterminated, bodyStart, bodyEnd`) for both `powershell: false` and `powershell: true` over: (i) every command string in this file's heredoc, disclosed-miss and command-position rows plus the eight delimiters the issue names (`E:F`, `E*F`, `E+F`, `E=F`, `E,F`, `E@F`, `E!F`, `EOF~`) each in a terminated and an unterminated form, each followed by `gh pr merge 5`; (ii) a seeded pseudo-random corpus of 3 000 strings (a fixed LCG seed written in the test; length 1–40) over the alphabet ``a b _ - . : * ( ) # $ < > ' " \ ` | & ; space newline tab`` plus the tokens `<<`, `<<-`, `<<<`, `$(`, `((`, `<#`, `#>`, `EOF`. A divergence fails naming the input as a JSON string. (iii) Two mutant rows proving the lock bites: the template's port with the paren arms removed and with the narrow delimiter class restored must FAIL the corpus — done by asserting that the two locked rows from 2855 now project (`spawnedPayload()` equals `{repo, pr: 5, headSha}`), which is exactly the behaviour those arms add.
4. **The flipped rows.** `(true)#<<note\ngh pr merge 5` and `cat <<E:F\nbody\nE:F\ngh pr merge 5` move from the never-spawns loop to positive `spawnedPayload()` rows; `(#<<note\ngh pr merge 5\n)` and `(true; echo a)#<<note\ngh pr merge 5` are added beside them.

### Edge Cases & Traps

- **Backslash doubling in the template literal.** Core's `HEREDOC_AT` regex renders in the wrapper as `/^<<(-?)[ \t]*(?:'([^'\n]+)'|"([^"\n]+)"|\\([^\s'"\\<>()|&;]+)|([^\s'"\\<>()|&;]+))/`; in the template source every backslash is doubled. Author it with the Edit tool and verify the RENDERED wrapper's regex by reading the scaffolded file, never by reading the source.
- **Arm order.** `$((` before `((`, and `((` (with `boundary`) before the bare `(` arm; `<<` after the quote and comment arms — as core orders them.
- **PowerShell.** Core's `ps` branch (the backtick escape inside double quotes; `<# … #>`) ports with the rest; the parity test runs both modes.
- **The `body` field.** Dropped from the wrapper's span (unused); the parity comparison omits it on both sides.
- **No behaviour change in core.** Only a comment line; core's own suites (`transport-shield.test.ts`, `transport-shield.fold.test.ts`) must pass unchanged.
