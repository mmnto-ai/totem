## Lesson — line to a minted id (D2b (a) at the S6 regeneration

**Tags:** wind-tunnel, fixtures, rule-scaffold, serving-writer, prettier, s6-regeneration

**Applies-to:** infrastructure

A wind-tunnel fixture's filename keyed on a rule hash (test-<hash>.md) is a live reference, not a label: rule scaffold checks for an existing fixture by that filename (rule.ts), and the spine-adopt spike pins the path in two record-set sources under a path-filtered workflow. Repointing a fixture's rule: line to a minted id (D2b (a) at the S6 regeneration, mmnto-ai/totem#3062) without renaming leaves rule scaffold <minted-id> free to write a second fixture; renaming reaches into the spike. The regeneration kept the filename and disclosed the hazard (read 1, F9); a minted-id filename rides the spike's own re-point. Related trap met in the same step: the export renderer's markdown is not prettier-stable on a first pass (escaped underscores in bold headings), so pnpm format:check fails after totem rule serve until prettier --write has run twice.
