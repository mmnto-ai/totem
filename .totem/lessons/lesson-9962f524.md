## Lesson — The deposit bare-ref scan reads the decoded strings

**Tags:** json, bare-reference, legs-deposit, validation, review-triage
**Scope:** packages/core/src/artifacts/legs.ts, packages/cli/src/commands/legs.ts, packages/cli/src/commands/init-templates.ts

Core's `saveLegDeposit` and `totem legs deposit` refuse a deposit that carries a bare `#NNN` reference by walking the PARSED file's strings and keys, not by scanning its text (mmnto-ai/totem#3025; error code `LEG_DEPOSIT_BARE_REF` on both). The second falsification leg measured why the text is not the authority: a reference authored as the JSON escape of the hash sign passes a text scan with zero matches and decodes to a bare reference in the stored file, and a qualified reference whose slash is JSON-escaped is refused by a text scan although it decodes qualified. The decoded string is what the deposit carries. The order is parse first: an unreadable or malformed file keeps its "Could not read the leg's findings" refusal, and a bare reference in it is caught once the JSON is fixed, with nothing written in between; the issue's original wording asked for a text scan before the parse, and the deviation is recorded on mmnto-ai/totem#3023. The pattern is single-sourced as `BARE_REF_REGEX_SOURCE` in core; the rendered write shield's copy in `packages/cli/src/commands/init-templates.ts` is a second literal, held equal to core's by a test after the third leg found none asserting it.
