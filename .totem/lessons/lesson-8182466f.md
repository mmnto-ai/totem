## Lesson — A changeset clause is a claim the falsification read

**Tags:** changeset, falsification-leg, review-round, process

**Applies-to:** any

**Scope:** .changeset/

Four changeset clauses across the S6 step 1 and step 2b pull requests (mmnto-ai/totem#3038, mmnto-ai/totem#3039) were falsified before merge and rewritten: "compiles exactly as before" (the guard now reports a schema failure ahead of `CONFIG_MISSING`, `NO_LESSONS` and the option checks, and parses the file once more per run); "never a lesson hash" (a lowered row's id has the same 16-hex shape; what differs is that it matches no current lesson); "refuses on every path" (false until the unreadable-file fold, because the loader returns empty on a parse failure); and "a legacy row with no engine is advisory" (unreachable: `engine` is a required enum at `compiler-schema.ts:530` and at the type level, so the clause described a state the core test reaches only with a cast). The pattern: a changeset is written at the end from what the author believes the diff does; the falsification leg reads it as a list of claims against the source and a probe, and each overstated clause costs a fold. Write every clause from a measured behaviour (the test that shows it, or the probe), name the condition under which it holds, and drop a clause whose state cannot occur. Disclosure of a wider behaviour (B1's refusal on a corrupt file in a lesson-only repository) belongs in the changeset as a listed case with the refused inputs named, not as a general sentence.
