## Lesson — Gemini CLI reads workspace settings from its cwd only

**Tags:** gemini-cli, mcp, doctor, workspace-trust
**Scope:** packages/cli/src/commands/doctor.ts

Gemini CLI 0.61.0 loads `.gemini/settings.json` from the directory it is started in, with no walk up to the repository root. Measured: `gemini mcp list` from this repository's root lists the project-level server, and from `packages/cli` it does not; the installed bundle's `loadSettings` defaults to `process.cwd()`. A session started below the root has no project-level MCP servers whatever the trust state, so the `Gemini Workspace Trust` row judges only the directory `totem doctor` runs in. A walk-up would report a verdict for a folder the session is not in (mmnto-ai/totem#2999; the datum and its unmeasured half, whether the root's `GEMINI.md` still loads there, are on mmnto-ai/totem#2933).
