## Lesson — A batch set id digests its own rows as compact JSON bytes

**Tags:** whitelist, set-id, hashing, gate5, determinism
**Scope:** packages/cli/src/commands/authored-whitelist.ts, packages/cli/src/commands/authored-whitelist.test.ts

A Gate 5 class set's id is `static-whitelist@gate5-<sha8>`: the first 8 hex of the sha256 over ONE compact JSON array of the batch's own rows in committed order, each row serialized as `{ engine, structuralClass }` in that key order, with no whitespace and no trailing newline (`setDigest` in `packages/cli/src/commands/authored-whitelist.test.ts`, which pins each batch's digest over its own slice of the table). The input is the slice, never the union: the batch-4 id `b5bc711a` digests 217 bytes for three rows, and a one-row batch still digests a one-element array (batch 3, 72 bytes), not the bare object. The falsification leg on mmnto-ai/totem#3020 recomputed the id and ran thirteen wrong inputs, none of which digests to it: the union of batches 1 to 4, all sixteen rows, the union of batches 1 to 3, the five other orders of the three rows, the swapped key order, the pretty-printed block, a trailing LF, a trailing CRLF, and the three objects concatenated without the array. The ids of batches 1 to 3 do not move when a batch lands, and the same rule reproduces all four from the committed table. The intake pin passes the id as `--judged-by` verbatim and the scorer records it from the PR and the pin mail, so a digest over any other bytes would bind the ledger rows to an id no table carries.
