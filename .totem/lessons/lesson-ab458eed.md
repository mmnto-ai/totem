## Lesson — A line-window requires admits its token anywhere on the line

**Tags:** regex, requires, absence-construct, gate5, review-triage
**Scope:** .totem/rules/mig-7e3eefea-lesson-heading-separator.rule.yaml, .totem/rules/mig-b3e3e2b3-git-lc-all.rule.yaml, packages/core/src/spine/rule-record.ts

A record's `requires: { pattern, scope: line }` suppresses the target match whenever the pattern appears anywhere on the same line, so a legacy lookahead anchored to the match becomes wider when translated to the line window. Two batch-4 records carry it (mmnto-ai/totem#2950): `mig-7e3eefea` requires `' [—–-] .+'` on a `## Lesson` heading, so a heading whose separator sits later on the line (`## Lesson: foo - bar`) is a legacy firing the record suppresses; `mig-b3e3e2b3` requires `LC_ALL=C` on a `git` line, so `LC_ALL=C sort f; git diff` is a legacy firing the record suppresses. Both widenings are the pre-registered inventory (ii) transformation (a must-contain lookahead to a `requires:` block at the `line` window, Prop 310 § Design 8), stated verbatim in the batch's translation notes with the measurement over the pinned tree (removed 0, added 0 on both), and both rules are kept out of the intake envelope on engine typing with no whitelist row and no ledger row. Greptile raised both at the intake pin as P2 findings; each premise was true by construction and each was deferred to the Gate (5) report as a curation datum, not fixed: V1's `requires.scope` name space is `line | block | file` with `block` reserved-unimplemented (`packages/core/src/spine/rule-record.ts`), so no narrower window exists to anchor the check to the match, and the records are translation-bound paths the scorer's attestation binds byte-for-byte. The cure is a grammar question for the post-spine record, a narrower-than-line window; a reviewer's "anchor it to the prefix" ask on a pinned record is answered by the notes' widening line and the window name space, never by an edit.
