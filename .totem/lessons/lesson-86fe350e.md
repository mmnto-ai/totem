## Lesson — isProseGlob checks the glob dialect before the extension

**Tags:** globs, whitelist, fail-closed, falsification-leg, spine
**Scope:** packages/core/src/spine/authored-rule.ts, packages/core/src/spine/rule-record.ts

A whitelist row tagged `scope: 'prose'` is decidable only when every declared glob is a prose glob, and core's `isProseGlob` decides that in a fixed order (mmnto-ai/totem#2996): a glob that `checkGlobDialect` refuses is not a prose glob; then the last path segment is taken, and a wildcard-only segment is not one; then the final extension, lower-cased, must be one of `PROSE_EXTENSIONS` (md, mdx, rst, txt). The dialect step was a fold. The first falsification leg ran the built predicate without it and got three wrong answers from the public export: the empty string produced a refusal that the result's own schema rejected, a glob with a leading negation mark read as prose although the mark means negation to the matcher, and a glob with a leading space read as prose. None is reachable through `totem rule author`, where the record parse checks the dialect first, but the predicate is exported, so it fails closed for a caller outside the intake, and the recorded `glob` of a refusal accepts any string so that the refusal is recordable exactly as passed. Removing the dialect check fails 2 of 59 tests. The bring-forward leg's probes at the merge head: brace expansion, a bracket class, a question mark and a trailing slash are refused by the dialect and so are not prose; the extension compare ignores case; a double extension that ends in a source extension, a bare directory glob and the long-form markdown extension are not prose; a dot-file named only by a prose extension counts as prose, which is the rule's letter. For a dialect-legal glob the predicate errs only toward refusal.
