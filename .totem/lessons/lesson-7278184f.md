## Lesson — A message that reports what a helper did is measured

**Tags:** init, pilot, messages, tenet-4, bot-round, trap

**Applies-to:** presentation, boundary

A message that reports what a helper did is measured by the helper's own read, never by a read beside it. On mmnto-ai/totem#3084 the init message said whether the pilot state file was initialised, already present or re-initialised; the first cut derived that from a second existence check next to the helper, so a transient read failure inside the helper (a reset after a file it could not read) printed as a fresh initialisation (Greptile's second pass, 2026-10-14, P2). The fold made the helper return its outcome (readPilotStateWithOutcome) and the message print that outcome; the test asserts the message against the helper's returned outcome, not against the file system after the fact. The same shape as a receipt that re-derives what a step did instead of carrying the step's own result.
